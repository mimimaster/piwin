# Pi 0.80.10 → 0.84.2

Pinned in `@piwin/agent-host`:

- `@earendil-works/pi-ai` `0.84.2`
- `@earendil-works/pi-coding-agent` `0.84.2`

`pnpm typecheck` green. `agent-host` 250 tests green, including the real `DefaultResourceLoader` discovery-block test.

## Why no new adapter

`agent-host` already isolates Pi:

- dynamic `import('@earendil-works/pi-coding-agent')` + missing-export checks
- local types (`PiModelRuntime`, session handle duck types)
- `event-map` reads `message_update.assistantMessageEvent.delta` (0.84 dropped cumulative `partial`)

That is the compatibility layer. A second wrapper would only duplicate it.

## `finish_reason`

`resolvePiModelCompat` sets `compat.supportsFinishReason: false` on every
`openai-completions` model (DeepSeek profile keeps its other flags). Pi then
infers `stop` / `toolUse` when the SSE stream ends without `finish_reason`,
instead of throwing and auto-retrying. Anthropic / Google registrations are
unchanged.
