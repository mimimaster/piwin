# ADR 0038: Host egress delivery authority, flow control, and client recovery

| Date | 2026-08-08 |
| Trigger | Main Desktop WebContent reached 9.9–16.5 GB and was terminated by WebKit during active runs |

## Context

During active model/tool runs, one normalized provider delta currently creates
more than one product push and native WebView delivery:

1. `HostRuntime` emits the normalized `event` push.
2. `RunRegistry.noteAgentEvent()` emits `run/updated` even when the public Run
   record did not change.
3. The CLI-local stream batcher treats `run/updated` as a global barrier and
   flushes the pending delta.
4. Rust emits every JSONL line through a separate Tauri `host-message` event.
5. Tauri/WRY uses a separate WKWebView JavaScript evaluation for each event.
6. Desktop replaces the full `runRecordsById` map for each Run echo, making all
   mounted transcript rows fail their memo identity check.

Local evidence recorded 12,000–15,000 native-to-WebView JavaScript evaluations
per minute and repeated WebKit renderer termination. WebKit attributed most of
the footprint to `bmalloc` and compressed allocation churn, not to a giant live
JavaScript heap.

The package dependency graph was not violated. The missing boundary is an
operational one: `HostPush` specifies payload shapes, but no component owns
delivery semantics, priority, pacing, per-client capacity, replay, or overload
behavior end to end.

ADR 0036 already requires bounded queues, fan-out, replay, and snapshot
hydration for remote clients. This incident makes those properties a local
Desktop reliability prerequisite.

## Decision

### 1. Domain authorities publish revisions, not observation echoes

`@piwin/host-runtime` remains the Run/session/tool authority. It publishes a
replaceable projection only when a public projection field changes.

For `RunRegistry` the invariant is:

```text
one semantic Run state change  → at most one run/updated revision
zero semantic Run state change → zero run/updated revisions
```

The first model delta may set `firstTokenReceived` and transition the Run to
`streaming`. Repeated same-phase text, thinking, and tool-output deltas do not
publish another Run record. Terminal state remains Host-owned and lossless. `AgentEvent.error` is
execution evidence and display data; it never terminalizes a Run by itself.
Lost client delivery recovers from RunRegistry plus transcript, not by
letting Desktop infer a terminal from an error event.

Only Host egress creates `AgentEventEnvelope`. `@piwin/agent-host` returns
plain normalized `AgentEvent[]`.

`ExecutionRunRecord` gains an additive monotonic `revision` generated by the
Run authority. Clients use it to reject duplicate/stale projections; transport
sequence remains a separate concern.

### 2. One Host egress hub owns the data plane

`@piwin/host-server` owns one `HostEgressHub` between `HostRuntime` and every
client transport:

```text
HostRuntime
    │ one non-blocking broker sink
    ▼
HostEgressHub
    ├─ semantic delivery classifier
    ├─ scoped ordering barriers
    ├─ canonical sequence + bounded replay journal
    ├─ per-client subscription/filtering
    ├─ bounded priority queues and pacing
    └─ metrics / overload disposition
          ├─ local JSONL batch connection
          ├─ loopback WebSocket connection
          └─ private WebSocket / future tunnel connection
```

Production client sockets do not attach directly to `HostRuntime.pushSinks`.
The Hub attaches once, ingests each semantic push once, and isolates slow
clients below the domain boundary. The existing multi-sink API may remain for
bounded internal observers, but it is not a bypass around egress policy.

The Hub never blocks or cancels a Host Run because a UI is slow. Host work and
transcript persistence continue when all clients are disconnected.

### 3. Delivery semantics are exhaustive and transport-owned

Every `HostPush` variant is classified by a pure, exhaustive classifier owned
by `@piwin/host-transport`. Adding a new push variant without assigning a policy
is a compile/test failure.

| Delivery policy | Meaning | Examples | Overload behavior |
|-----------------|---------|----------|-------------------|
| `control` | Lossless, low-latency lifecycle or user-decision data | permission request, message/tool end, Run terminal, error, Host readiness | Reserved capacity; never dropped; disconnect a client that still cannot accept it |
| `append` | Ordered content where every byte/item matters | text/thinking/tool deltas, child stream, PTY output, Job logs, transcript append | Aggregate into bounded batches; never silently drop; slow client disconnects and hydrates |
| `projection` | Full replaceable state for one entity | non-terminal Run update, browser frame/state, pet state, todo/plan/status projections | Latest value wins per stable entity key |
| `diagnostic` | Operational information that must not starve product control | host logs, browser console/network telemetry | Bounded oldest-first eviction with explicit counters |

Snapshot/hydration is a recovery mechanism, not a fifth high-rate push lane.

The delivery policy is not added to Pi events and is not inferred in React.
`agent-host` continues to normalize Pi payloads only.

### 4. Ordering barriers are scoped to dependent keys

A non-stream event is not a global flush barrier. A control push flushes only
pending data that it semantically closes:

- `message/end(m1)` follows pending deltas for message `m1`;
- `tool/end(t1)` follows pending output for tool `t1`;
- `run/terminal(r1)` follows pending append data for Run `r1`;
- a permission request can preempt unrelated streams;
- activity in session A never forces all pending data for session B onto the
  wire.

The classifier returns stable delivery keys and barrier scopes. Those keys are
specified in [`../specs/host-egress-delivery.md`](../specs/host-egress-delivery.md).

### 5. Sequence is assigned after canonicalization and before fan-out

ADR 0027's direction remains correct, but sequence placement is refined:

1. `HostRuntime` emits an unsequenced semantic `HostPush`.
2. The Hub applies the short aggregation window, replaces redundant projection
   values, and evicts bounded diagnostics.
3. Only canonical records that remain receive a Host-global `seq` and
   `eventId`.
4. Canonical records enter the bounded replay journal, except pushes marked
   `journal: false`. Subscription OAuth `auth/prompt` and `auth/login-finished`
   are ephemeral: reconnect uses `auth/status.activeLogin`, never a journaled
   callback URL or respond value.
5. Per-client subscription and queue policy produce a cursor-bearing batch.

This prevents intentional projection replacement from manufacturing apparent
sequence gaps. Transport sequence is scoped to `hostInstanceId`; a new Host
instance invalidates a client's old cursor.

The canonical wire unit is an additive `push/batch` frame. It carries:

- the client's previous cursor (`afterSeq`);
- the highest canonical sequence examined (`throughSeq`);
- zero or more ordered sequenced push items in that interval.

Items may be absent because they were filtered or a replaceable intermediate
projection was superseded. Advancing `throughSeq` explicitly distinguishes
policy-driven omission from a lost transport frame. Append items are never
omitted unless the connection is failed and the client is required to recover.

The older singular `push` frame remains a protocol-v1 compatibility input
during migration. New servers advertise batch/cursor capabilities and new
clients consume batches atomically.

The optional `seq`/`eventId` fields currently intersected into `HostPush` are
compatibility fields only. Canonical sequencing lives on the wire envelope;
new code must not copy different UUIDs into both the outer frame and inner
push.

### 6. Per-client queues are bounded and priority-aware

Each client connection owns independent control and data queues. Queue limits
are enforced by both item count and encoded bytes.

The overload order is fixed:

1. replace queued projections by key;
2. evict bounded diagnostics and increment counters;
3. aggregate append items into the next bounded wire batch without losing
   their content/order;
4. preserve capacity reserved for control;
5. if the client still cannot keep up, close only that connection with the
   stable `slow-consumer` reason;
6. on reconnect, replay from the bounded journal or explicitly hydrate.

The Hub does not use an unbounded promise chain, socket send queue, Rust event
queue, or JavaScript callback queue as hidden buffering.

### 7. Local Desktop migration happens in two safe stages

#### Stage 1 — bounded Tauri batch bridge

- Keep the current Node sidecar and JSONL framing.
- Route local pushes through the same Host egress policy as WebSocket clients.
- Write one bounded `push/batch` JSONL frame per data cadence, not one line per
  semantic push.
- Route responses only to the pending Rust request; do not broadcast them to
  WebContent.
- Emit push batches only to the `main` WebView, not application-wide.
- Desktop consumes a batch in one client transaction. Local WebViews coalesce
  deltas only until the current JavaScript task's microtask checkpoint. Stream
  visibility never depends on `requestAnimationFrame` or a timer because
  background/occluded WebViews may throttle either; lifecycle and control
  events still bypass the batch.
- The client detects cursor gaps (`afterSeq` beyond the applied cursor) instead
  of healing over them silently. A gap notifies the UI layer, which reconciles
  against Host authority. Gap detection and window refocus on a thread that
  still shows a live run are the normal triggers; a newly admitted Run also
  gets a bounded 250ms/1s/3s/5s convergence window for a terminal push that
  was lost after admission. This is bounded recovery, not an unbounded polling
  loop.
- Reconciliation queries `session/foreground-run` (the Run registry is the
  authority). A terminal record replays the terminal projection; no record at
  all clears stale streaming state; an active run means do nothing. The
  transcript tail is re-pulled first because a lost terminal push usually also
  lost the final assistant text.
- The JSONL sidecar writer isolates per-line failures: one rejected write must
  never poison the serialized chain into dropping all later output.

This stage is the incident containment/release gate.

#### Stage 2 — authenticated loopback HostClient

- Tauri starts/stops the Host and returns an ephemeral loopback endpoint plus a
  per-launch credential through one bounded invoke.
- The public `@piwin/host-client` connects directly to the loopback Host Server.
- Tauri remains the process supervisor; it is no longer the streaming data
  plane.
- The listener binds to loopback only, uses an ephemeral port, validates the
  accepted Tauri/dev origins, and never logs the credential.

The Stage 1 JSONL batch transport remains a valid fallback while Stage 2 is
proven; neither path may bypass the Hub.

### 8. Client projection and rendering are independently bounded

Transport flow control is necessary but does not authorize global UI
invalidation. Desktop must also:

- ignore identical or stale Run revisions;
- pass a row only the Run record it renders, never the whole Run map as row
  identity;
- process a Host batch atomically and coalesce live stream UI updates arriving
  in the same transport task;
- keep the Markdown renderer's live text projection on Streamdown's streaming
  tree. An animate-plugin *object* is passed only so Streamdown skips
  `startTransition` (WKWebView starves that path). `isAnimating` stays false
  so word spans are not injected; the live caret is CSS `.has-stream-caret`;
- keep the active response as a live tail while historical turns are immutable;
- window dynamic-height transcript turns and preserve scroll anchoring;
- unmount collapsed heavy thinking/tool/detail bodies;
- make tool-output byte accounting incremental;
- defer syntax highlighting of changing code fences until the fence is stable
  or the message is terminal.

The selected transcript windowing implementation is
`@tanstack/react-virtual`: it is headless, MIT-licensed, supports React 19 and
dynamic element measurement, and lets piwin retain its existing components and
scroll chrome. The dependency and rollout threshold are recorded in the
execution plan.

### 9. Renderer restart is a supported reconnect

A WebContent termination is a client disconnect, not a Host restart. The local
Desktop therefore uses the same recovery rules as a remote client:

- compare `hostInstanceId`;
- resume from the last atomically applied `throughSeq` cursor;
- replay when the cursor remains in the bounded journal;
- receive an explicit `replay-too-old` result when it does not;
- hydrate current transcript, active Runs, pending permissions, plans, and
  session runtime projections before declaring the client ready;
- apply pushes after the snapshot cursor without duplicating transcript data.

The existing status-only `HostSnapshotFrame` is insufficient and will be
extended with a hydration manifest plus typed Host queries. Snapshot/replay
ordering is detailed in the delivery spec.

### 10. Egress metrics are queried, never streamed as telemetry

The Hub retains bounded counters for:

- ingress and canonical pushes by variant/policy;
- source-to-wire coalescing ratio;
- batches/bytes per connection;
- queue depth and byte high-water marks;
- replaced projections and evicted diagnostics;
- slow-consumer disconnects;
- replay records/bytes and snapshot fallbacks.

These counters are returned by a local/admin diagnostic command or doctor
surface. They are not emitted as another high-frequency `HostPush`.

## Package ownership

| Package/app | Responsibility after this decision |
|-------------|------------------------------------|
| `@piwin/contracts` | Additive wire batch/cursor/capability/snapshot shapes; no queue implementation |
| `@piwin/host-runtime` | Domain authority; semantic revisions only; one broker sink |
| `@piwin/host-transport` | Wire codec plus pure delivery policy/key/barrier primitives; no HostRuntime or React |
| `@piwin/host-server` | Egress Hub, replay journal, per-client channels, WebSocket/local connection adapters |
| `@piwin/host-client` | Batch validation, cursor/dedup/replay/snapshot state machine, typed subscriptions |
| `apps/cli` | CLI/stdio composition only; no independent streaming policy |
| `apps/desktop/src-tauri` | Host lifecycle and legacy local batch forwarding; no per-push business policy |
| `apps/desktop` | Keyed client projections, final visual scheduling, transcript windowing |

No new Pi dependency is introduced. `@piwin/agent-host` remains the only Pi
boundary and does not gain delivery throttling.

## Desktop renderer containment addendum

Transport flow control removes the event multiplier but does not permit the
renderer to retain work proportional to an unbounded transcript. Desktop
therefore projects long history through stable, dynamic-height turn windows;
unmounts collapsed heavy detail; caps each visible tool-output projection at an
exact UTF-8 byte budget; and defers syntax highlighting while source is still
streaming. The cosmetic pet overlay is a separate Vite/WebContent entry and no
longer boots the main Desktop graph.

These are downstream containment layers, not substitutes for Host egress or
durable history. Automated bounds are implemented. Gate A remains open until a
clean native 30-minute run records the WebContent slope, delivery counts,
queue/cursor statistics, and Stop latency.

## Consequences

- The immediate redundant Run regression is fixed at its authority, not hidden
  with a Desktop debounce.
- Local and remote clients share the same queue, pacing, replay, and overload
  semantics.
- Client count and subagent concurrency no longer multiply serialization work
  without a per-client bound.
- A slow UI can lose its live connection, but cannot corrupt append content,
  starve control events, block the Host, or grow Host memory without bound.
- JSONL remains a valid framing transport, but one semantic push no longer
  implies one JSONL line, one Tauri event, or one React commit.
- Replay storage remains bounded; durable product state, not an infinite token
  journal, is the recovery source of truth.
- The current in-progress `host-transport`, `host-client`, `host-server`, and
  `apps/host` skeletons become the implementation base. They must be reconciled
  with this decision rather than duplicated.

## Supersession and addenda

- **ADR 0006:** sidecar/JSONL remains valid, but the one-message/one
  `host-message` event data plane is superseded by bounded batches.
- **ADR 0015:** async turn/control-lane semantics remain valid; this ADR adds
  the symmetric outbound priority and flow-control contract.
- **ADR 0027:** multi-sink and replay direction remain valid. Sequence is now
  assigned by the Egress Hub after canonicalization, and the CLI-local stream
  batcher is not reusable as the canonical policy implementation.
- **ADR 0030:** RunRegistry remains the sole lifecycle authority; unchanged
  observation echoes are explicitly forbidden.
- **ADR 0036:** Phase 0 bounded egress/replay/snapshot work is pulled forward as
  a local reliability prerequisite before multi-client rollout.

## Rejected alternatives

- **Remove only the transcript fade/mask.** This reduces compositor risk but
  leaves native event and global render amplification intact.
- **Debounce only in React.** Tauri serialization and WKWebView JavaScript
  evaluation have already occurred.
- **Throttle in `agent-host`.** Product transport policy would pollute the Pi
  boundary and could hide events required by Host recording/hooks.
- **Drop arbitrary text, thinking, or tool deltas.** This corrupts the
  transcript; append data is lossless while connected or recovered explicitly.
- **Make `PushSink.push()` await every client.** One slow phone or renderer
  would apply backpressure to the Agent authority and make control unreliable.
- **Use an unbounded replay/token log.** Durable transcript/snapshots are the
  long-term authority; replay is a bounded reconnect optimization.
- **Add a global Rust timer with no semantic keys.** It can reorder terminal
  and permission events relative to dependent stream data.
- **Increase the WebKit memory limit or restart earlier.** This hides a broken
  data plane and normalizes state loss instead of repairing it.
