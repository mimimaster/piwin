1. 背景与目标解释

普通对话（Conversation）中，同会话切换提问路线已可用。项目 / Agent 会话复用同一套控件，但在会改写工作区文件的环境中， 「对话变了什么、磁盘会不会变、已发生的副作用是否被掩盖」此前解释不一致，容易误导。

产品负责人确认开工后，执行目标锁定为修订计划中的加强版 P0：统一探索入口的写边界确认、可恢复校准、失败重试证据保留，以及项目会话「再生成」门控。 目标文案「完整执行」按计划 Risks 节解释为完整加强版 P0，而非全路线图。

分层（保持）

  • 对话路线 · 历史与模型上下文
  • 工作副本 · 仓库文件隔离
  • 文件撤销 · 可验证恢复（独立能力）

本轮焦点

  • 入口级上下文与文件状态可解释
  • 离开有写入的尝试须确认
  • 取消不改变当前路线

明确不做

  • 整树预览 / 从节点继续（P1）
  • 关联会话 + worktree（P3）
  • 热 Pi branch()（P2）

编号 标准 结果
AC-1 凡离开当前尝试且观察到工作区写入的探索入口（切换兄弟路线、编辑 / 开分支再发、丢弃式重试）须先拒绝并要求确认；取消后活跃路线不变。 已达成
AC-2 项目 / Agent 会话不暴露成功轮 keep-previous「再生成」；Conversation 仍可；失败轮无 keep-previous 重试仍可用。 已达成

AC-4 丢弃式重试删除失败尝试后，写入证据仍可查询（不随唯一助手行一并消失）。 已达成

3. 交付内容

3.1 Host：统一离开写边界

  • session/prompt 的编辑分支（branchFromMessageId）与丢弃重试（retryUserMessageId）在未确认时分别以 branch-leaves-writes / retry-discards-writes 拒绝，并附结构化 WorkspaceWrites。
  • session/branch-switch 继续使用既有 needs-confirmation 路径；确认后排队校准。
  • 离路 branchFromMessageId 对 listAbandonedAssistantRows(targetId) 求放弃写入（与 switch 对齐），避免父节点仍在活跃路径时误得空列表。

3.2 可恢复校准

  • 待校准写入会话目录 pending-branch-calibration.json（原子写），进程内 Map 仅作缓存。
  • injectBranchCalibrationOnce：先注入模型可见块，成功后再清除 Map 与磁盘文件。
  • 切换、编辑分支、丢弃重试（带写入）确认后均调用 queuePendingBranchCalibration。

路径 · ~/.piwin/sessions/<sessionId>/pending-branch-calibration.json

3.3 丢弃重试证据

  • 在 truncateFrom 之前，将观察到的写入合并到用户消息元数据字段 discardedAttemptWrites。
  • 合约 SessionTranscriptMessage 与 transcript store 行映射已同步；证据可经 getMessage 查询。

3.4 Desktop：确认流与再生成门控

  • 编辑 / 开分支拒绝后弹出确认卡；意图 intent="leave-branch"（「编辑会离开当前尝试…」），不再套用「切换分支」文案。
  • branchResend 与 retryTurn 对齐：Host 接受前不裁剪 transcript、不乐观 user/send；写边界拒绝时可见路线不变。
  • 项目会话隐藏 keep-previous 再生成；Conversation 保留；失败重试仍走 keepPrevious: false。

首轮交付后，对抗性评审指出三处缺口；均已修复并纳入回归。

6. 非目标与后续阶段

8. 收尾建议

  1. 范围签收：确认「加强版 P0 完成」即本轮目标；全路线图另立项。
  2. 工程收口：按关注点拆分小 commit（Host 写边界与校准 / Desktop 确认流 / 合约与 store / 文档），避免与无关工作区改动混提。
  3. 可选实机签收：在项目会话上走一遍：切换有写入的兄弟路线 → 取消 / 确认；编辑再发 → 确认文案与路线不变；丢弃重试后检查 discardedAttemptWrites；重启 Host 后下一次 prompt 仍见校准块且仅一次。
  4. 下一刀选型：产品根据近期反馈在「简化版 P3」与「收敛版 P1」之间二选一优先。
