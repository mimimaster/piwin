## 0. 为什么重设计，重设计什么

- 现状：Deck（`docs/adr/0061-deck-design-system.md`，`docs/design/deck-design-system.md`）是"你拥有的一件仪器"路线——
  悬浮面板、Iris/Ember 双信号、Inter + JetBrains Mono。与此同时，产品里还叠着一层"泼墨写意 · 深夜书案 / 砚"水墨母题
  （`apps/desktop/src/ink-wash-assets.ts`、`ink-wash-empty-vignette.tsx`、`styles/*-ink-wash.css`），只用于空态与点缀。
  **两套人格并存，没有一个贯穿全部界面的主题。**
- 目标：一个主题贯穿 `00-scope-inventory.md` 里的全部 UI 块（外壳 17 项、转录 8 段 + 16 类卡片、作曲器 ~20 控件、
  检视器 10 页签、对话框/菜单 ~30、设置 13 节、子页 7 面）。布局允许重排；**交互契约保留**（键盘、IME、运行语义、权限门）。
- 方式：增量交付。每个增量 = 一份可打开的原型 + 一页说明；负责人看过再进下一步，不一次性铺满。
- 不做：本轮只出设计与原型，不改 `apps/desktop` 代码；不动架构边界（AGENTS.md §1–§2）。

## 1. 工具选择：为什么不以 Stitch 为主力

- 复用了已存在的 Stitch 项目 `projects/16447086721780536055`（"piwin - Neo-Deck AI Coding Agent Shell"，含 3 个已生成屏幕）做评估。
  产出是标准的"深色 + 靛蓝 + 圆角卡片"AI IDE 模板：结构合理，但**无产品词汇**（没有权限门、队列/介入、子代理、走查报告、
  水墨母题的痕迹），也无法表达状态（idle / running / waiting）与双面（浅/深）。
- 生成一屏要数分钟且不可增量微调；主题一致性靠再跑一遍模型，无法保证。
- 结论：**主力用手写自包含 HTML 原型**（Canvas 内直接可看、可切浅/深面与运行状态、可落盘、可直接转成 token 实施）。
  Stitch 保留为"第二意见"工具：某一屏定稿前可用 `generate_variants` 拿几张变体对照。

## 2. 范围 → `00-scope-inventory.md`

盘点方法：4 个只读 scout 分别覆盖外壳/页面、视觉语言与历史、转录与作曲器、对话框与检视器；结果按模块合并、去重、标注实现文件。

## 3. 主题 → `01-inkstone-theme.md`

主题名 **Inkstone（砚）**：把已有的"砚"印章与"深夜书案"从点缀升级为全局语义——
纸（浅面）/ 墨（深面）两张脸；**朱** = 你的手（主操作、焦点、待批准）；**灯** = 机器的手（运行中）；
**印** = 批准（盖印即允许）；**砚** = 作曲器（页面上唯一一块深色石板）。
"文人的安静，不是戏服"：母题只在语义、少数签名物件和空态出现，99% 的界面是克制的现代工作台。

## 5. 交付物约定

- 每份原型：单文件、无外链、顶部有"纸/墨"与"状态"切换，1440×900 设计画布按窗口缩放。
- 所有文案中文优先、英文/路径等宽；标签与真实实现里的 i18n 文案对齐（引用 `apps/desktop/src/desktop-locale.ts`）；
  提议改文案时在该增量说明的「差异清单 · 文案」行列出来源文件。
- 每个增量末尾附"与现实现的差异清单"（保留 / 重排 / 新增 / 删除 / 文案），方便后续实施拆片。
- 原型与说明同一增量内一起落盘（AGENTS.md §4：一切落盘）；负责人的确认写回本表「状态」列。
