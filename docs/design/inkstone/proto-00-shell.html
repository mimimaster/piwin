去掉各类外部框架的包装，Agent 的本质就是一个基于工具调用的 while 循环：将带有 tools 描述的消息数组发给模型，若模型产生 tool_calls，则在本地执行并将结果以 role: tool 消息追加回上下文，再次请求，直至模型给出最终自然语言回答。

去掉繁杂包装，单 Agent 核心运转闭环只需这十数行精炼代码：

minimal_agent.py·Python 
def run_agent_loop(client, prompt: str, tools: list):
    messages = [{"role": "user", "content": prompt}]
    while True:
        res = client.chat.completions.create(model="claude-sonnet-4-6", messages=messages, tools=tools)
        msg = res.choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            return msg.content
        for call in msg.tool_calls:
            out = execute_local_tool(call.function.name, call.function.arguments)
            messages.append({"role": "tool", "tool_call_id": call.id, "content": str(out)})

外壳负责驱动这个循环，并通过流式推送将思考与工具产物呈现在舞台纸面上。

研墨深思 · 结构化报错反馈与状态机自愈反馈环（Reflection Loop）
绝不能在本地直接 throw 异常中断进程。关键是将异常包装为一条特殊的 role: "tool" 消息反哺给模型：包含报错原因与期望的 JSON Schema，让模型在下一轮循环中阅读自己的调用失误并自动修正。

自愈修正的核心是「报错即工具产物」。不要中断循环，将解析异常捕获并回填：

self_healing_agent.py·Python 
try:
    args = json.loads(call.function.arguments)
    result = execute_local_tool(call.function.name, args)
except Exception as err:
    # 自愈反馈：让模型在下一轮看到具体语法/参数错误并自我纠偏
    result = {"status": "error", "message": f"参数解析失败: {err}，请严格按照Schema修正后重试"}

设置最大连续错误预算（如 3 次），模型通常在第 2 次循环即可完成自我纠偏。

自愈修正状态机的流转闭环如下：

agent_self_healing.mermaid·Mermaid 
graph TD
    Start([用户提问]) --> Loop[模型决策循环]
    Loop -->|产生 ToolCall| Parse{参数校验与反序列化}
    Parse -->|校验成功| Exec[执行本地工具]
    Parse -->|解析异常| ErrMsg[构造自愈提示消息]
    ErrMsg -->|作为 Tool 消息入栈| Loop
    Exec -->|工具执行产物入栈| Loop
    Loop -->|无 ToolCall| Done([输出最终答复])

该机制使得 Agent 对复杂输出具备极佳鲁棒性，无需脆弱的外置硬解析脚本。
