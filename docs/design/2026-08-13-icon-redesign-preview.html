piwin 图标重设计

proposal v1 · 2026-08-13 · 仅预览，未接入产品
Design Language

设计语言

现状是三套图标并存：桌面端手绘描边、ui-kit 引入的 Tabler 成品（笔画 2.0、风格更圆钝）、以及 Run 状态的多彩渐变图标。 本提案将全部收敛为一套自绘系统 —— 更轻、更一致，并带一处来自品牌标的记忆点。

terminal · 24×24 grid · stroke 1.6

24×24 网格，1.6 笔画

与产品 CSS（16px 渲染、stroke-width 1.6）完全对齐；圆角端点与拐角，关键点落在 0.25 网格上。

双层次单色

主笔画 + 45% 透明辅助层（折角、经线、键帽等次要信息），比纯描边多一层精致感，仍随主题色继承。

统一几何词汇

同一个文档形、同一个窗口圆角（rx 2.4–3）、同一个圆（r 8.25）、同一副 chevron，在所有图标间复用。

克制的语义色

图标本体一律 currentColor；只有文件标识与 Run 状态携带产品语义色板（暖金 / 青瓷 / 琥珀 / 绯红）。

签名元素「光标块」 —— 取自品牌标里 P 旁边的青瓷插入点。只出现在 terminal、agent、canvas、working 这几个身份图标上，其余图标保持安静。
File Badges

文件标识

现版直接使用 Tabler 的品牌 logo（React 原子、Python 双蛇、HTML5 盾…），形状密度参差、色值取自 Tailwind 且饱和度不一。 新方案改为统一圆角色块（tile）+ 字标 / 符号：语言用两三字母，JSON / HTML / Shell / 图片用更直觉的符号； 色板整体压到同一亮度带，与产品暖色调协调。文件夹与未知文件保持描边形态，用于区分「容器 / 叶子」层级。

Run Activity

Run 状态图标

现版每个状态一套渐变 + 多色叠加（右上角小图），信息密度高但很吵。新方案回到单色几何： 形状表达状态、语义色表达结果（金＝进行中，琥珀＝等待授权，绿＝完成，绯红＝失败），动效只保留一处最小循环。 working 状态复用签名光标块。动作类小图标（terminal / edit / search / web / subagent）为纯 currentColor，跟随所在行的文字颜色。

Notes

范围与落地说明

本提案覆盖

  • 90 个语义图标 → 替换 packages/ui-kit/src/icons/shell-icons.tsx（Tabler 映射）与 apps/desktop/src/shell-icons.tsx（手绘版），两套合并为一套，公开名称保持不变。
  • 14 个文件标识 → 替换 packages/ui-kit/src/icons/file-type-icon.tsx 的 Tabler 品牌图标与旧色板。
  • 15 个 Run 状态图标 → 替换 apps/desktop/src/RunActivitySvgIcons.tsx 的渐变风格。

不动的部分

  • 应用 logo / 品牌标（docs 里的 brand-mark 与 Tauri 应用图标）—— 按要求排除。
  • Provider 厂商标（OpenAI、Anthropic 等，来自 modelicons）—— 第三方商标，不宜重绘。
  • MCP 官方链环标已按新笔画重绘为「协议节点」形（见开发与系统组）；若你希望保留官方 mark 以维持社区辨识度，落地时可以只保留旧版，这一点待你拍板。

待确认

  • Q1 文件标识的「tile 字标」方向是否 OK？备选是无底色纯字母（更轻）或全符号系统（更抽象）。
  • Q2 签名光标块的出现范围（目前 4 处）要不要收紧 / 放宽？
  • Q3 Run 动作类图标是否需要保留分类色（现为跟随文字色）？
