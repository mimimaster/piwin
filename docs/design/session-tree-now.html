代码现状 · 不是 ADR

会话树现在是什么，
项目会话差在哪

Conversation（普通对话）里这套已经好用：改一句提问、发出去、旁边出现 ‹2/2›，点一下就能回来。 项目会话用的是同一套控件。不是没做，是同一套东西被放进会改文件的环境里，文案和一两个按钮没跟着变。

先记住一件事。 Host 不区分 Conversation / 项目。树、切叶、‹n/m›、编辑重发，两边走同一条命令。 Desktop 顶栏只要有 activeSessionId 就会挂「会话树」。 所以你在 Conversation 里觉得顺手，项目里那套控件其实都在。

2. 为什么 Conversation 用起来顺

手势短

改提问 → 发送新版本 → ‹2/2› 出现。想回来就点一下。空态那句话就是在教这个：「改写某一轮的提问后发送，会在这里留下一个分叉。」

分叉没有代价

对话里几乎不写盘。切叶等于换一页聊天记录。没有 Git 芯片抢「branch」这个词，也没有工具循环把主区撑满。

所以 Conversation 的会话树已经是成品：同一条会话里试另一种问法。 项目会话不需要另做一棵树，把这套手势留着就对了。

3. 项目里实际别扭的，是这几处代码

不是「项目不能用树」。是同一套 UI 在会改文件的会话里，有三个地方会让人误会。

① 「重新生成」两边都挂着

chat-thread.tsx 里：最新助手气泡 + 有 onRetryTurn → 就给「重新生成」。 没有看 isConversationSession。 Conversation 里这就是再答一遍，没事。 项目里上一轮可能已经改了一堆文件，再生成一版只换对话、不撤磁盘，‹n/m› 却看起来像「回到没改文件之前」。

② 顶栏文案还是聊天语气

副标题写的是「在这条会话的分岔之间切换」。空态只教改提问。 确认框其实已经写了「磁盘不会跟随」——但那是写过文件、你已经要点切的时候才看到。 空态和顶栏没提前说。

③ 三个都像「分叉」

会话树 / ‹n/m› = 本会话对话叶。
「从这里分叉」= 新开一条会话，项目下默认还是同一工作区。
Git 芯片 = 换代码分支 / worktree，可能再开一条项目会话。
Conversation 里你几乎只碰到第一个，所以不乱。项目里三个并排。

4. 建议（按 Conversation 已经验证过的手势来）

不要给项目重做一棵树。把 Conversation 那套原样留下，只改项目里会骗人的边。

  1. 1 项目会话拿掉「重新生成」。这是最小、最值的一刀。
    失败仍然用错误卡「重试」（丢掉这次尝试）。 想换方案：编辑提问 → 发送新版本 / 开分支。这就是 Conversation 已经教会用户的路。
  2. 2 项目顶栏加一句实话，空态同步改。
    例如：「分叉的是对话，不是代码。切换不会还原工作区。」 控件不用改，确认框那句话提前说就行。
  3. 3 别让三个入口抢同一个词。
    会话树继续叫会话树，副标题用「对话分岔」。 「从这里分叉」可改成「开新会话」（它本来就是）。 Git 芯片继续管 git，不要画进会话树。
  4. 4 「先暂存再切换」可以留，但别假装是隔离。
    它是同一仓库的 git stash，不是新工作区。
  5. 5 worktree / 文件倒带先不要塞进这棵树。
    并行隔离已经有 Git 芯片（换 checkout = 新会话）。 撤 agent 改过的文件如果以后做，做成单独动作，不要做成「切 ‹n/m›」。
