# iOS 壳：像聊天应用一样好用（交互重设计）

- 日期：2026-09-27
- 范围：`apps/mobile/src/inkstone`（iPhone / iPad 同一套）
- 状态：已定，随本 spec 实现

## 1. 问题

产品负责人实测后的结论：iOS 壳“跟传统 chatbot 不一样，反而不好用”。具体是：

| # | 现状 | 为什么差 |
|---|------|----------|
| P1 | 会话页点「+」进入「新的一页」表单页：选模型、下拉选项目、在大文本框里写想法，再点「开始这段会话」 | 所有聊天应用都是点「+」直接进空白对话，光标就在输入框。多一个表单页 = 多三步决定 |
| P2 | 桌面端分「对话（chat）」和「Agent（项目）」两种会话，手机端混在一个按项目分组的列表里 | 找不到自己要的那段；闲聊被当成“一般会话”项目挤在工程会话中间 |
| P3 | 每段会话的输入框上都挂着「计划 / 工作区 / 任务 / 上下文」四个胶囊，顶栏还有工作区按钮 | 对闲聊毫无意义，视觉噪音大，像 IDE 不像聊天 |
| P4 | Apple Health：手机端有“附带健康数据”的完整链路（`includeAppleHealth`），但 inkstone 输入框里没有任何入口；只能去 案头 → 设置 → Apple Health | 用户根本不知道能用，也不知道这一轮有没有带 |
| P5 | Host 读取 Apple Health 的工具调用被折叠在「工作过程」里，和 `ls` / `grep` 一个待遇 | 传统 chatbot 会把“已读取 健康 · 步数、睡眠 · 近 7 天”作为来源卡片直接展示；现在完全看不到 |

## 2. 设计原则

1. **聊天优先**：打开 → 看到会话 → 点「+」→ 直接打字。任何“先决定再开始”的步骤都延后到用户需要时，且有合理默认值。
2. **两种会话，两种界面**：对话会话 = 干净的聊天界面；Agent 会话 = 带项目、计划、工作区等工程工具。和桌面 `SidebarMode`（`chat` / `code`）同一划分：`scope.kind === 'project'` 即 Agent，其余为对话。
3. **能力看得见**：设备能力（Apple Health）在输入框的「+」里就能开，开了有胶囊标记；模型用了它，回复里有可见的来源卡片。
4. **不造空会话**：点「+」只开草稿，第一条消息发出时才在 Host 上创建会话（ChatGPT 同款），避免列表里堆满“Mobile session”空壳。

## 3. 方案

### 3.1 会话首页：顶部「对话 | Agent」分段

- 标题栏下方一个分段控件：`对话` / `Agent`，选择记在本机（`piwin.mobile.session-mode.v1`，localStorage，仅偏好）。
- **对话**：只列 `scope !== 'project'` 的会话，按时间平铺，不画项目标题；「置顶」仍单独一节。
- **Agent**：只列项目会话，沿用按项目分组的树；「全部 / 进行中 / 置顶」筛选保留在这一侧。
- 「接着上次 / 正在工作」卡片只在 Agent 侧出现（它本来就是为长任务设计的）。对话侧不需要大卡片，列表本身就是入口。
- 大标题「会话 · 日期 · 思路仍在继续」去掉，把首屏留给列表。Host 连接卡片保留但压成一行。

### 3.2 「+」= 直接开一个空白对话

- 点右上「+」：进入**草稿会话**页，模式 = 当前分段（对话 / Agent），输入框自动聚焦。
- 草稿页是完整的聊天界面：空态中间一句问候 + 3 个示例（点了填入输入框，不直接发送）。
- 发送第一条消息时：`session/create`（对话 → `scope: general`；Agent → 选定项目）→ 切到新会话 → 发送。失败时文字留在输入框。
- 删除旧的「新的一页」表单页（`#new` 路由）。

### 3.3 Agent 草稿：项目是输入框上的一个胶囊

- Agent 草稿的输入框上方显示 `📁 <项目名> ▾` 胶囊，默认 = 最近用过的项目（最新一段项目会话的项目），没有则取 Host 项目列表第一个。
- 点胶囊弹出项目列表（选完关闭，仍在草稿页，不创建会话）。
- Host 没有任何项目时，胶囊显示「无项目 · 按对话开始」，发送时退回 general 作用域，不阻塞用户。

### 3.4 会话页按模式裁剪 chrome

| 元素 | 对话 | Agent |
|------|------|-------|
| 顶栏工作区按钮 | 隐藏 | 显示 |
| 计划 / 工作区 / 任务 胶囊 | 隐藏 | 显示 |
| 上下文胶囊 | 隐藏（到 80% 以上才出现，提醒压缩） | 显示 |
| 模型按钮、语音、「+」附件 | 显示 | 显示 |
| Apple Health 胶囊 | 开启时显示 | 开启时显示 |

### 3.5 Apple Health 进入对话

- 输入框「+」弹层第一行：`Apple Health`。
  - 已连接且可用：点一下切换“本轮附带健康数据”，弹层关闭，输入框上出现 `♥ Apple Health ×` 胶囊（点 × 取消）。
  - 未连接：副标题「未连接 · 点按设置」，点按跳到 设置 → Apple Health。
  - Host 不支持客户端工具：副标题说明原因，不可点。
- 回复中：Host 调用健康工具（`presentation.kind === 'health'`）时，在回合正文**上方**画一张可见的来源卡片：`♥ 读取 Apple Health · 已完成`，第二行是时间范围与指标（`近 7 天：步数、睡眠 · 更新至 …`），点开看时区、缺失指标、提示。卡片不再折进「工作过程」。复用 `health/HealthToolCard` 的状态映射。

### 3.6 不做的事

- 不改 Host 协议；不新增 contracts 字段。所有改动在手机壳内。
- 不改 Apple Health 的授权 / 同意流程（`HealthConsentDialog` 保持）。
- 底部导航（会话 / 动态 / 知识 / 案头）不动。

## 4. 验收

1. 会话页点「+」：一步进入空白对话，键盘弹出；发送后列表出现一条新会话，名字由 Host 生成。
2. 切到「对话」只看到非项目会话；切到「Agent」只看到项目会话；杀掉 App 重开，分段保持。
3. 对话会话页没有计划 / 工作区 / 任务胶囊和工作区按钮；Agent 会话页有。
4. Agent 草稿显示默认项目胶囊，可切换；发出后新会话归属该项目。
5. 「+」弹层能开关 Apple Health，开启后输入框有胶囊；Host 读取健康数据时回复上方有可见卡片。
6. `pnpm typecheck`、mobile 测试通过；新增纯逻辑（模式划分、默认项目、健康步骤拆分）有单测。

## 5. 第二轮体验审查（同日）

逐页走查后的修正，原则都是“正常状态不说话，只有需要注意时才出现”：

| 位置 | 问题 | 处理 |
|------|------|------|
| 会话列表 | 每一行都有绿色状态点 | 只在「正在工作 / 等你批准」时显示 |
| 会话列表 | 没有预览时副标题是「1 条消息」「等待继续」 | 不显示副标题 |
| 会话列表 | Host 连接卡片常驻占一行 | 只在未连接时出现 |
| 会话页顶栏 | 每页都挂「等待你的下一笔 · 127.0.0.1:8787」 | 只在工作中 / 待决定 / 暂停时显示状态；空闲时 Agent 显示项目名，对话不显示副标题 |
| 会话页 | 对话会话也有「生成走查报告」 | 仅 Agent 会话提供（走查报告审的是代码变更） |
| 输入框 | 底部常驻「已同步」 | 只在连接中 / 创建会话中显示 |
| 会话页 | 往上翻后没有办法回到最新 | 离开底部时，输入框上方出现 ↓ 按钮 |
| 会话菜单 | 「继续到项目」实际是打开别的项目会话；「在桌面继续」写明不可用 | 两项删除；常用项（重命名、置顶、导出）在前，归档在最后 |
| 动态页 | 底部导航没有高亮项；空状态是红色提示条「今日待办已更新」 | 修正高亮；标题与 tab 统一为「动态」；空状态改为说明性文字 |
| 动态 / 案头 | 半屏的诗句大标题 | 去掉，内容上移 |
| 弹层标题 | 「把上下文捎进来」「先说，再落笔」「找一段思路」等 | 改为「添加到这一轮」「语音输入」「搜索会话」等直白说法 |
