## 1. 结论

保留「闪卡」唯一入口和卡片库默认首页，在卡库内增加明确的「开始复习 / 继续复习」入口，进入独立、可随时离开的**复习台**。

复习台不是新的知识中心，也不是常驻三栏工作台。它是一张当前卡、一条进度、一组回答动作，以及始终可见的出口。来源和伴学只在需要时展开。

核心验收：**一眼知道在学什么，一次操作离开，回来不丢位置；看过不等于记住。**

方法：阅读官方产品帮助与交互原则资料，访问日期 2026-08-30。没有登录并实测这些产品，也没有做用户访谈；以下是资料事实与 piwin 设计推论的区分。

| 来源 | 官方资料确认的行为 | 对 piwin 的启发（设计推论） |
|---|---|---|

| [RemNote：Practicing Specific Flashcards](https://help.remnote.com/en/articles/6904503-practicing-specific-flashcards) | 支持全局到期队列，也能按文档、文件夹或筛选后的集合练习；间隔复习与全卡练习是不同模式 | 入口可以带上卡组上下文，复习空间统一；浏览顺序不冒充调度顺序 |
| [RemNote：The Flashcard Home](https://help.remnote.com/en/articles/7925835-the-flashcard-home) | 首页能启动全局复习，也能从具体文档启动；展示复习相关进度 | 只借鉴可发现的复习入口，不照搬目标、连续天数和统计大首页 |
| [Quizlet：Studying with Flashcards](https://help.quizlet.com/hc/en-us/articles/360030988091) | 提供翻卡、前后导航、学习分组；移动端帮助明确提到 X 退出保存进度，但该模式进度不跨设备同步 | “退出”可以是保存并离开，不应成为惩罚；piwin 正式版用 Host 持久状态，不复制该跨设备限制 |
| [NN/g：User Control and Freedom](https://www.nngroup.com/articles/user-control-and-freedom/) | 强调用户能离开流程、撤销操作并回到之前状态 | 把返回、暂停和撤销视为主流程能力，而非菜单里的补丁 |

不照搬：Quizlet 的整卡点击翻面会与 piwin 卡内划词冲突；Anki 答案面 Space 自动选择 Good 容易与连续空格翻面习惯冲突，第一版保留显式评分和 1–4。这里是适配产品情境的取舍，不是断言竞品设计不好。

## 4. 信息架构

```text
会话 / 侧栏
  └─ 闪卡（唯一的家；图库默认首页）
       ├─ 点开一套 → 浏览（不评分、不改变复习计划）
       ├─ 开始 / 继续复习 → 复习台 → 本轮小结
       └─ 出卡 / 新增 / 管理（保留现有能力）
```

入口规则：

- 卡库顶部：有中断会话时优先显示「继续复习 · 已完成 x / n」；否则「复习到期卡 · n 张」。
- 卡组层：独立「复习这组」，带 deck 范围；点卡本体仍是浏览，避免管理意图被强制转成考试。
- 聊天产卡：继续保留就地预览；显式「到复习台」才进入学习，不重定向聊天消息。
- 回到卡库要恢复原卡组筛选、搜索、滚动和触发按钮焦点；卡库本身再返回原会话。
- 不新增侧栏“学习中心”，不让每日目标和统计挤掉原卡库。

## 5. 复习台布局

| 区域 | 内容与行为 |
|---|---|
| 顶部导航 | 左「← 返回卡库」，中「复习台」及当前卡组，右「暂停」；正式版始终可见 |
| 进度 | 「本轮已完成 x / n 张」；开始为 0，不因揭晓答案增加 |
| 学习主区 | 居中、合理阅读宽度；正面保留问题，揭晓后在其下展示答案，减少前后翻面记忆负担 |
| 主操作区 | 未揭晓只有「显示答案」；揭晓后四档评分占同一区域，避免界面跳动 |
| 低优先级操作 | 撤销上次评分；提示、讲解与来源就地按需展开 |
| 完成状态 | 本轮复习张数、作答次数、值得巩固的卡；返回卡库为明确出口 |

空间规则：正式 Desktop 顶栏与操作栏稳定，长内容在中间滚动，不能把退出与评分推到长文末尾。小窗口四档按钮变 2×2。原型为对话内可展开预览，使用自然纵向布局，不锁浏览器视口，也不据此宣称正式版长内容滚动已验收。

视觉沿用 piwin 的中性底色、紫色强调和系统中文字体。UI/UX 技能的第一轮通用建议偏 AI 展示页，因此未采纳其配色与营销布局；窄化检索后采用面向生产力工具的简洁风格，并以返回可预测、焦点、对比度和操作优先级为约束。

## 6. 学习与恢复的交互规则

### 6.1 核心循环

1. 进入时先显示问题，不自动泄露答案；文字可以划选，点击正文不翻面。
2. 用户自行回忆，需要时主动索取短提示。
3. 点击「显示答案」或相应快捷键，问题留在上方。
4. 用户评分；Host 确认写入后进入下一张。
5. 队列结束显示小结，不自动开启新一轮，也不宣传“已掌握”。

评分文案：

| 文案 | FSRS 值 | 含义 |
|---|---|---|
| 忘了 | again | 答错或想不起来，不把“部分想起”归到 Hard |
| 费力想起 | hard | 答对，但回忆困难 |
| 记得 | good | 正常回忆出正确答案 |
| 很轻松 | easy | 几乎不费力地答对 |

正式版评分下方显示 Host 计算的下一次复习时间；不能前端写死“10 分钟 / 1 天 / 4 天”。第一版可先用语义解释，等 preview 协议落地后再加时间。

原型为便于几分钟内体验，将“忘了”的示例卡插到最多两张之后；**这不是 FSRS 调度实现**。正式版需要服从到期时间：有短期重学项时继续处理其他可用卡；剩余卡都未到期则显示“本轮已处理完，下一张将在……可复习”，允许直接离开，不通过乱改间隔制造完成感。

### 6.2 返回、暂停、关闭

- 返回卡库：正常路径一次点击完成，不弹“确定退出？”；已提交评分不撤销。
- 保存卡组、队列、当前 cardId、正/背面与进度；继续时回到原处。无需用户额外点保存。
- 暂停：隐藏题目与答案；恢复还原当前卡面，暂停期间不累计有效学习时长（若后续增加计时）。
- Esc：有辅助面板时只关闭最上层；否则回卡库。一次键盘事件只能产生一次退栈；不依靠多处 window 监听器碰巧配合。
- 点击窗外不退出；这是学习页，不是大面积背景点击即关闭的临时弹层。
- 窗口关闭与重启：已确认评分及 Host 会话可恢复。未确认提交显示“待确认 / 未保存”，绝不假报已保存。
- 断网或提交失败：当前卡不前进，保留用户选择并提供重试；如选择离开，明确未保存状态，重连以相同请求标识核对结果。该异常才需要提醒，不阻拦正常退出。

### 6.3 撤销、提示与浏览

- 「撤销上次评分」恢复评分前调度状态和队列，返回该卡答案面。不是再补交一条相反评分。
- 只撤销 Host 确认可撤销的记录；其他客户端已更新时报告冲突，不覆盖新进度。
- 提示只给线索；背面才提供解释、举例与来源摘录。辅助内容不写入聊天，不自动出新卡。
- 用过提示的卡可进入“值得再看看”清单，但不得静默替用户改评分；提示不等于正确作答。
- 浏览模式沿用相同视觉壳，但显示「浏览 · 不计评分」，保留顺序导航，结束只记“已浏览”。
- 正式复习按 ReviewCard 身份调度；卡库按 Item 身份展示。cloze 的多个空独立调度，不能被 sequenceId / position 替代。

## 7. 实施范围和架构

### 第一版必须闭合

卡库复习入口 → 独立复习页 → 评分 → 退出恢复 → 撤销 → 结束小结；支持 basic / cloze 的现有 Host 投影、错误与空队列。来源和短伴学复用已有能力，可按需展开。

暂不加：排行榜、打卡、番茄钟、三栏常驻 AI 聊天、复杂曲线、自动播放、花哨 3D 翻转、多种测验模式。这些不是修复当前复习体验的前提。

### 复用与需要补齐的能力

| 所属 | 复用 / 新增建议 |
|---|---|
| contracts | 在实施前定义独立 FlashcardReviewSession、queue / rating preview、resume / pause / undo 命令及响应；命名为建议，不表示这些 API 已存在 |
| flashcards | 复用 CardStore、ReviewState、FSRS、cloze 投影；新增复习会话存储、队列策略和撤销日志；纯状态转换单测 |
| host-runtime | 组合服务，处理幂等提交、并发 revision、恢复与 HostPush；保持唯一权威 |
| desktop | 独立复习页与状态控制器；复用 Markdown、划词伴学、来源打开及 ui-kit 按钮 / 对话框 / 提示，绝不从原型复制裸按钮作为正式实现 |
| CLI / mobile | 接入同一复习命令与状态；可暂不提供桌面式空间布局，必须明确展示层降级，不能另存一套评分 |

关键存储建议：复习会话与撤销数据落在 `~/.piwin/flashcards/` 下（最终布局在实施 ADR 明确），不用浏览器 localStorage 作为学习真值。当前 Item / ReviewCard 约定不变。复习会话不是 Agent Session，也不是 SessionPlan。

需要处理的工程边界：

- 双击评分、请求超时后重试使用同一 operationId；写入和推进队列保持一致。
- 保存评分前的 ReviewState 供撤销；校验版本，避免多客户端互相覆盖。
- 续学时检查卡片删除、cloze 空变化与内容更新；失效项从队列移除并说明，不“卡死在不存在的卡”。
- 当前 `ReviewState` 没有持久 FSRS 完整 learning/relearning 阶段；若第一版承诺精确短期重学，需补契约、迁移与 fixture 测试，不能只靠前端插队。
- 原始库的 item 数与展开后的 review-card 数分别命名，避免 cloze 数量不一致。
- 不引入 Pi 依赖到 UI / flashcards，不新建第二份卡库，不改调度算法参数来掩盖 UX 缺口。

实施顺序：先确认原型 → contracts / Host 持久会话与撤销 → Desktop 页面接线 → 多端契约与测试 → 更新旧规格及必要 ADR。

## 8. 原型范围

## 9. 验收清单

- [ ] 从卡库开始复习；正常退出只需一次点击或一次 Esc。
- [ ] 评分几张后退出，恢复同卡、同进度；揭晓但未评分后退出恢复答案面。
- [ ] 暂停隐藏卡片；继续不增减学习计数。
- [ ] 显示答案、提示和浏览不推进复习进度。
- [ ] 误评分可撤销，并真正恢复调度状态；重复请求不会重复记分。
- [ ] 第一张进度为 0；完成数不能由当前下标加一伪造。
- [ ] 先关辅助面板，再退出学习；一次 Esc 不跨两层。
- [ ] 键盘不抢占输入 / 系统快捷键；所有动作有可见按钮，文字选择不触发翻面。
- [ ] 评分失败、空队列、卡片被删除、重启及另一端更新均有明确状态。
- [ ] 窄屏四档 2×2，长内容不遮挡返回 / 评分，明暗主题均可读。
- [ ] 小结不称“永久掌握”，浏览不写评分，练习不悄悄改变到期计划。

这份清单是正式版验收要求，不代表本次静态原型已通过全部生产级测试。

## 10. 本次原型验证记录

已通过本机浏览器实际点击 / 键盘验证：

- 提示 → Esc 只收起辅助区；仍停留复习台。
- Space 揭晓；1 / 2 / 3 / 4 可评分；未揭晓时不显示评分按钮。
- 答案面暂停 → 恢复，同一卡、同一卡面；返回卡库 → 继续亦保持。
- 中途打开独立浏览，再回到复习，原复习答案面不被浏览覆盖。
- Again 不虚增完成卡数；隔两张再次出现；撤销回到原卡答案面。
- 示例混合评分一轮：5 张完成、6 次作答、2 张需巩固，与操作吻合。
- 结束后的最后一次评分仍可撤销，恢复为 4 / 5，停在最后一张答案面。
- 浏览可不揭晓直接前后导航，结束显示「已浏览 5 张」；复习仍为 0 / 5。

- 原型脚本语法检查通过，无 fetch / XHR / WebSocket；文件约 24 KB，223 行。

没有运行全仓 `pnpm typecheck` / 应用测试：本次只新增提案与任务外原型，没有修改运行时代码。`git diff --check` 通过；用户已有的 `transcript-markdown.css` 改动未触碰。
