# 本轮代码改动与撤销 — 产品及交互 Spec

| 字段 | 内容 |
| --- | --- |
| 状态 | **V2 / 待审，未授权实现** |
| 日期 | 2026-08-30 |
| 用户意图 | 这次提示词执行完，看到修改了几个文件、增加/删除多少行；不满意，点击「撤销」撤掉这轮代码改动 |
| 操作单位 | **一次提示词的实际执行（本轮 / 一个 Run）**，不是整个会话，不是整个目录 |
| 修订说明 | 本版完全替代 V1 检查点管理方案；沿用文档路径便于审阅，不沿用旧产品设计 |
| 交付边界 | 仅修订 spec；没有实现按钮、采集或撤销服务，没有执行任何项目文件回滚 |

## 0. 产品决定

正常路径只有：**看到本轮改动 → 点撤销 → 本轮已撤销**。撤错了，在原位置点「恢复改动」。

| ID | 决定 |
| --- | --- |
| TU-D01 | 沿用回答下方现有文件变更汇总条，展示「本轮修改 N 个文件 · +A −D」，右侧是「查看变更」「撤销」。 |
| TU-D02 | 「撤销」明确只处理该条汇总对应的一次执行；不自动连带其他轮次。 |
| TU-D03 | 正常情况点一次即执行，不强制预览、不选检查点、不弹常规二次确认、不勾确认框。 |
| TU-D04 | 撤销成功后原位显示「本轮已撤销」及「恢复改动」；恢复也只恢复这轮刚被撤掉的改动。 |
| TU-D05 | 文件范围、行数、详情和撤销必须来自同一份真实、持久的本轮变更记录。 |
| TU-D06 | 相关文件有后续改动、记录不完整或安全条件不满足时，停止自动撤销，说明原因；不提供强制覆盖。 |
| TU-D07 | 保留提示词、回答、当前对话分支及输入草稿；不自动重新执行模型。 |
| TU-D08 | 不新增顶部「文件检查点」、检查点列表、命名快照、目录恢复或「撤销本会话」入口。快照/备份仅为底层机制。 |

## 1. “本轮”与撤销范围

### 1.1 本轮如何界定

- 一条提示词被 Host 实际接纳执行，形成一个 Run；排队但未执行不产生文件变更记录。
- 本轮包含这次执行内的模型调用、工具循环和 steer；Pi 内部 provider 自动重试不另算一轮。
- 用户点重试产生新的 Run，单独记录。每次尝试绑定稳定的 sessionId、runId、userMessageId，不靠“第几条消息”猜测。
- 一轮内可能有多个助手消息，只显示一条本轮汇总，位于该次执行的最后一个助手消息下方。失败/中断且无最终回答时，挂在该轮结束状态行下方，不伪造助手正文。
- 同一提示词多次尝试时，汇总标注「第 N 次尝试」，对应当前可见尝试。切换回答不恢复磁盘文件，也不改变撤销目标。

### 1.2 撤销什么，不撤销什么

| 对象 | 本轮撤销行为 |
| --- | --- |
| 本轮修改的文件内容 | 撤回本轮记录的变化，保留执行前已有内容，包括用户未提交的修改 |
| 本轮新建的文件 | 删除本轮新建且仍符合安全校验的文件 |
| 本轮删除的文件 | 从记录恢复原内容和可执行位 |
| 本轮未改的文件 | 不作为写入目标、不修改、不删除 |
| 更早/更晚轮次、其他会话或手动改动 | 不自动撤销；与本轮文件重叠且无法安全分离时拒绝操作 |
| 提示词、回答、分支、草稿 | 全部保留，仅更新产品变更状态 |
| Git 提交、分支、暂存区；数据库、部署、网络副作用 | 不撤销，不声称“所有操作已回滚” |

首版采用保守的整文件指纹保护：只在受影响文件仍匹配本轮记录的结果时撤销；不做同文件后续改动的自动合并。**这只是避免覆盖后来改动的执行条件，不是把撤销范围扩大到整个目录。**

旧轮次也可点撤销，只要其变更仍满足条件。若第 4 轮又改了第 3 轮的同一文件，撤第 3 轮会被阻止，不自动连第 4 轮一起撤。撤销不保证保留下来的其他代码仍能通过测试；它只处理已声明的文件变化。

## 2. 入口与界面

### 2.1 主入口：回答下方的变更汇总条

~~~text
助手：已完成登录校验调整，并补充了测试。

本轮修改 4 个文件 · +120 −38       [查看变更] [撤销]
~~~

- 直接扩展现有 FilesChangedBar，不在顶部或提示词旁另造一个平行入口。
- 「本轮修改 4 个文件」可展开文件列表；「查看变更」打开该轮的详细 diff，两者都只读。
- 「撤销」使用文字按钮及撤销图标，与查看按钮分开，不把整条卡片设为危险点击区。辅助说明为「仅撤销这次执行的代码改动，聊天保留」。
- 常驻可见，不只在 hover 或右键菜单出现。窄窗口先换行排按钮，不把唯一撤销入口藏起来。
- 一轮完成、失败或中断，且变更记录结算后才允许撤销。运行中显示「正在记录本轮改动…」，不提供边运行边撤销。
- 已完整核实且没有净变化时显示「本轮未产生文件改动」，不显示撤销按钮。没采集到数据不能冒充零变化。
- 不要求用户提交 Git 或先建检查点；原本有未提交修改不妨碍记录本轮变化。

### 2.2 查看变更：复用右侧 Changes 区域

~~~text
Changes                                     [关闭]
本轮变更 · 第 3 轮 / 第 1 次尝试
Host：本机 · /work/example
4 个文件 · +120 −38                    [撤销本轮改动]

修改 src/login.ts             +42 −18
新增 tests/login.test.ts      +65  −0
修改 src/messages.ts          +13  −8
删除 src/old-validator.ts      +0 −12

文件差异：本轮修改前 → 本轮修改后
……
                                     [查看工作区全部变更]
~~~

- 从汇总进入，右侧必须处于「本轮变更」上下文，并绑定 runId；不能直接打开当前整个项目的 Git diff 冒充本轮 diff。
- 点文件进入对应差异，支持「返回文件列表」；关闭面板回到原回答和滚动位置，输入草稿不变。
- 「撤销本轮改动」与汇总的「撤销」调用同一操作，不另增确认步骤。
- 「查看工作区全部变更」明确切回原有 Git Changes 视图；该视图不因此获得本轮撤销权限，也不新增整会话撤销。
- 本轮上下文不显示暂存/提交或逐文件勾选撤销；原有 Git 功能留在工作区视图。
- 历史 diff 永远表示这轮当时做了什么，不随当前文件漂移；已撤销时保留 diff 并加「这些改动已撤销」状态，不把历史统计清零。

## 3. 正常闭环：一键撤销，再一键恢复

### 3.1 撤销

1. 用户看完回答，直接点汇总条右侧「撤销」。点击本身就是授权撤销这个明确的本轮变更集。
2. 按钮立即进入「正在撤销…」，防重复点击；Host 自动核验目标及当前文件，保存操作前安全备份，然后执行。
3. 无需弹窗；成功后原位变为：

~~~text
本轮已撤销 · 原修改 4 个文件 · +120 −38
聊天保留。                         [查看变更] [恢复改动]
~~~

4. 用户可继续输入、修改提示词或手动重试；系统不自动发送、不删除后续聊天、不切换分支。

### 3.2 恢复刚撤掉的改动

1. 在同一条汇总点「恢复改动」，只重新应用这轮刚撤掉的变化。
2. 重新做安全核验和操作前备份。若撤销之后相关文件又变化，则拒绝覆盖并显示原因。
3. 成功后原位显示「本轮改动已恢复 · 4 个文件 · +120 −38」，按钮回到「撤销」。
4. 恢复不启动模型、不重新跑工具，也不重新运行测试。重复撤销/恢复可以使用同一变更集，但每次都生成独立操作记录并重新核验。

### 3.3 返回、离开与重启

- 撤销/恢复不改变聊天滚动位置、不抢输入焦点。结果状态持久保存在汇总条，不依赖几秒后消失的 toast。
- 关闭详情、切换会话或客户端断线不取消已接纳的文件操作；回到该轮可看到真实状态。不能把网络超时显示成“已撤销”。
- 接纳后不提供可能产生半写入的强制停止按钮。核验/备份阶段原位提供「取消」，只有首写前 Host 才可接受；已首写则说明「已开始写入，正在安全完成」，安全完成或回退。
- 正常使用无需打开操作记录。兜底入口在现有 Changes 区域提供的可见「更多」菜单 →「代码撤销记录」，只列当前工作区的撤销/恢复操作，不列检查点。详情可查看结果、返回原轮次或恢复该次撤掉的改动；保留返回记录列表和关闭出口。
- 源消息已删除时，记录标明来源不可定位；仍可在保留期内恢复对应操作。旧操作已被后续撤销/恢复替代时，只读，不重复提供过时的恢复按钮。

## 4. 冲突和其他异常：只在需要用户处理时打断

### 4.1 相关文件后来被修改

在原汇总下显示，不先弹一个“是否强制”的对话框：

~~~text
无法撤销：2 个文件在本轮结束后又被修改。
为保留后续改动，本次未修改任何文件。
                          [查看冲突] [重新检查]
~~~

「查看冲突」在右侧展示受阻路径、已知修改来源、本轮历史 diff 和当前文件差异；来源未知就写“来源未知”，不能猜是用户还是其他会话。若明确是后续轮次，提供「定位到后续轮次」，由用户自行决定是否先撤它。

首版不提供强制覆盖、自动合并、自动级联撤销或“先撤其中几个文件”。点「重新检查」只检查，条件恢复后重新显示「撤销」，不因等待结束自动执行。

### 4.2 状态与出口

| 状态 | 展示 | 出口 / 行为 |
| --- | --- | --- |
| 本轮运行/收尾中 | 正在记录本轮改动… | 可看已知文件；不能撤销未结算记录 |
| 有已知后台写入未结束 | 后台操作尚未结束，暂不能撤销 | 查看任务；不自动停进程 |
| 同工作区其他运行仍活动 | 工作区仍有任务运行，暂不能撤销 | 查看任务、重新检查；不排队自动执行 |
| 采集不全、归属不明 | 本轮改动记录不完整，无法自动撤销 | 查看已记录变更及缺失原因；不假装完整 |
| 已过期 / 旧版本无备份 | 本轮没有可用的撤销数据 | 查看现有历史摘要；不拿 HEAD 代替 |
| 核验/备份失败 | 撤销未执行，文件未改变 | 显示权限/磁盘等原因；重试或打开已有诊断入口 |
| 当前文件冲突 | 文件已再次变化，无法安全撤销 | 查看冲突、重新检查 |
| Git 基线变化/相关文件已暂存 | 当前 Git 状态不满足安全撤销条件 | 查看工作区变更；不自动取消暂存或回滚提交 |
| 正在写入/验证 | 正在撤销（或恢复）N / M 个文件… | 可离开视图，不能重复提交；不报假成功 |
| 中途失败并安全回退 | 撤销未完成，已还原到点击前状态 | 查看失败原因、重试；不是“本轮已撤销” |
| 中途失败且无法安全回退 | 部分文件需要修复 | 查看修复详情；阻止相关工作区新写入 |
| 客户端断线 | 结果尚未确认，正在重连… | 按原 operationId 查询，不再次执行 |
| Host 不支持/目录不支持/无权限 | 明确的不可用说明 | 不出现能执行的撤销按钮；不自动初始化 Git |

修复详情列出每个路径、操作前备份及当前校验结果，提供「导出备份」「重试修复」「重新验证」。导出到用户选定的新位置，不覆盖工作区；重试先确认受影响路径，遇外部新内容不强写。只有验证文件已回到操作前状态才解除修复阻塞。Host 重启也必须能从持久日志恢复此状态。

## 5. 文件数与行数：显示的就是要撤销的

### 5.1 统计口径

- 统计本轮**净变更**，不是工具调用次数，也不是“曾经碰过的文件”数量。同文件写十次最终只计一次；改完又完全改回不计净变化。
- +A / −D 来自本轮实际前后内容的统一文本 diff。不是相对 HEAD 的整个工作区差异，不解析模型回答，不按输入字符数估计。
- 新增文件计全部新增行，删除文件计全部删除行；行尾、无末尾换行等由统一 diff 实现处理，各端不自行计算。
- 二进制和仅模式变化计文件数，但行数为不可计算/不适用；展示如「4 个文件 · 文本 +120 −38 · 含 1 个二进制」，不伪造 +1。
- 首版重命名可规范化为旧路径删除 + 新路径新增，计 2 个路径项；列表注明此口径，统计和操作范围保持一致，不依赖模糊重命名识别。
- 若存在未知或未记录修改，文案为「已记录 N 个文件 · 记录不完整」；不能用这个数字声称覆盖本轮全部改动，也不能开放“完整撤销”。
- 工具报错并不代表没有写文件；部分成功的写入必须纳入实际记录。失败/中断轮次同样有撤销需求。

### 5.2 当前实现需要改变的地方

现有 files-changed-bar.tsx 用工具路径过滤当前 git/diff-summary，collect-message-changed-files.ts 还存在按工具输入估算行数和跳过失败工具的回退逻辑。这些可以辅助旧版展示，但**不能作为本轮精确统计或撤销依据**。

新增 Host 权威的 TurnChangeSet 取代新轮次的展示数据源。旧历史若没有真实记录，标明无法自动撤销；不能事后用现在的文件伪造执行前状态。

## 6. 底层约束：保证只撤本轮，不扩大范围

### 6.1 记录自己的写入

1. Host 在实际执行前建立记录上下文；文件写工具记录可验证的写前/写后内容、存在性、类型、可执行位及路径。
2. 同一文件多次写入按本轮动作顺序合成；若写入之间出现不能解释的内容变化，不能把它并入“本轮贡献”，整轮标记不可自动撤销。
3. 运行前后目录快照可以用于发现遗漏、保存对象，但**目录快照之差本身不是改动归属证明，更不是撤销目标列表**。真正写入范围只能来自已结算的本轮变更集。
4. Shell/自定义工具不能只凭命令名称猜写入路径。需要受控执行边界的前后采集与写入关联；无法确认归属或发生并发外部写入时标明不完整，不能默认归到本轮。
5. 普通 Host 文件工具的准确记录是首版必达路径；任意 Shell/MCP/外部进程产生的写入不宣称全部可归属。没有受控记录的写入只可展示“无法自动撤销”的边界，不用猜测填满覆盖率。
6. 关联本 Run 且实际合入当前工作区的子任务写入才属于本轮；独立 worktree 内尚未集成的内容不算父轮改动。集成要有独立可验证记录。
7. 记录包含 workspaceId/Host/真实目录身份；界面路径相同不代表同一工作区。不得对搬迁后无法识别的目录自动恢复。

此处是设计约束，不声称普通文件系统能证明所有写入来源或提供 OS 级排他。MCP 仍按 ADR 0033 位于权限层之外，本功能不更改该边界。

### 6.2 一键执行仍要核验

- UI 提交明确的 changeSetId、显示版本、方向 undo/redo 和幂等键，不提交“把这个目录恢复”的请求。接纳后的操作不再依赖消息仍然存在。
- Host 获取重叠工作区的短期写入门禁，核验本轮已结束、没有相关活动写入、数据完整、客户端授权及项目信任。
- 撤销前，所有目标文件必须与记录的本轮结果一致；恢复前，必须与最近成功撤销的结果一致。校验内容、类型、存在性、模式及父路径安全；不只比较文件名。
- 首版同一受影响文件即使只是别处多改了一行，也拒绝自动撤销；不相交文件的后续变化不扩大操作范围。不能把此限制误报为支持精准三方合并。
- 验证 Git 身份/基线没有不安全漂移；受影响路径有暂存或冲突时拒绝，无关暂存状态不变。不使用真实 Git reset/clean 或 HEAD checkout 代替本轮撤销。
- 校验展示版本与目标清单不变；显示后记录变化则零写入拒绝，刷新后由用户重新点按钮。用户授权的范围不能在后台悄悄扩大。
- 先完整保存本次操作前备份和恢复日志，再开始写入；预检任一路径失败，整次零写入。多文件写入不能假定原子，失败要安全回退，回退不确定则进入修复状态。
- 门禁覆盖 Host 接纳的新 Run、Git 写操作和子任务集成；不擅自停止已经运行的任务。外部编辑器/进程仍可能竞争，写入前后复核；发现外部新内容不能在回退时强行覆盖。
- 不支持路径越界、符号链接跳转和特殊文件；删除本轮新建文件时不递归删除父目录，已有目录与其中其他文件不动。

### 6.3 持久化与继续对话

- 变更集、操作日志和对象保存于 Host 的 ~/.piwin/，建议独立 turn-changes/ 子目录；不依赖 Pi TUI 示例的内存 stash 映射，不 fork Pi。
- 建议普通变更对象保留 30 天；每次操作前备份至少保护 7 天，成功撤销后支持「恢复改动」的数据至少再保护 7 天，详情展示确切到期时间。操作摘要至少保留 90 天。未终结/需修复操作的数据不得因到期清理。
- 初版建议 Host 使用 5 GiB 软预算、单文件 20 MiB 上限；排除 Git 元数据、产品自身状态、已知凭据和依赖/缓存等。不承诺识别所有秘密。超限或本轮修改了无法记录的路径时，明确覆盖缺口，不开放整轮自动撤销。
- 达预算时先清理已到期且无保护引用的数据；不能保存安全备份就拒绝撤销。采集失败不阻止用户原任务，但该轮及时提示无自动撤销保障。
- 不为此新建检查点管理页面。容量问题展示用量、原因和已有诊断出口；调整保留策略属于后续独立管理能力。
- 元数据在消息裁剪、重试替换、分支切换后仍可关联原 runId。归档不删除数据；永久删除会话时明确提示操作记录/安全备份按保护期保留，内容不暗中随聊天导出到另一 Host。
- 成功后 Host 推送工作区 revision 与实际操作事实，刷新实时文件/Git 视图。下一次任何受影响会话执行/继续时，模型收到文件已撤销/恢复的事实，重新检查文件，不继续把旧工具结果当当前状态。

## 7. 范围、多端与既有功能

- 首版落地范围建议为 Git 项目的普通受管文件，支持已有未提交修改、本地 checkout、现有 worktree 及远程 Host；非 Git 目录明确不可用，不自动初始化仓库。这是实现覆盖建议，不改变“仅本轮”语义。
- Desktop 与 CLI 同一 Host 服务、同一统计与门禁；远程 Desktop 在详情展示 Host 和目录，不在客户端同名目录操作。
- CLI 提供本轮查看、撤销、恢复、操作查询。明确命令即授权该轮，不默认扩成当前会话；自动化调用必须指定预期变更版本，防止目标漂移。建议语义如下，参数随 contracts 落实：

~~~text
piwin turn changes <runId>
piwin turn undo <runId> --expected-version <version>
piwin turn redo <runId> --expected-version <version>
piwin turn operation <operationId>
~~~

- 记录查询、导出备份及修复共用 Host 能力，CLI 不能成为绕过冲突的强制覆盖后门。Mobile 首版只读同步汇总/状态，不提供写入口；恢复锁仍拦截手机发起的新写入。
- 纯聊天无文件操作时不出现汇总或撤销入口；旧版 Host 通过 capability 降级，不发送未知命令。
- 模型运行模式 auto/ask/bypass 不替代用户点击；撤销能力不注册为模型工具，artifact HTML 不能直接触发。
- 现有“编辑/重试”“切分支”“删除对话”行为不与撤销自动联动。本 spec 不顺带重做这些功能。

## 8. 契约、复用与实现归属

| 归属 | 责任 |
| --- | --- |
| packages/contracts | 拟新增 TurnChangeSet、TurnChangeFile、TurnChangeOperation、availability/reason、命令与推送；保持叶子依赖 |
| packages/git | 按职责实现内容对象、变更集合成、diff/统计、文件校验与日志化 undo/redo；复用公开 Git/path safety 能力，不把其他应用包上层逻辑塞进来 |
| packages/host-runtime | Run 绑定、写入采集协调、权限、门禁、生命周期、跨客户端同步和模型状态校准 |
| packages/agent-host | 仅 Pi SDK/RPC 事件与工具适配；如需记录端口由 Host 注入，不向上依赖 Git/其他应用包 |
| packages/session | Run/消息映射及可查询元数据；不让文件撤销改变对话树 |
| Desktop / CLI / Host transport | 消费公共 contracts；共用 Host 实现，不各写一套恢复算法 |

最小协议语义：读取本轮摘要、分页文件清单、按需历史 diff、undo、redo、操作查询/订阅、工作区操作记录、写前取消、修复检查/执行/验证及只读备份导出。undo/redo 使用期望版本与幂等键，返回 operationId；断线只查询，不生成新操作。内容读取按对象和 manifest 授权，不接受任意路径读取 Host 文件。

变更记录和撤销进度使用独立 HostPush 变种，不伪装成 Pi AgentEvent。稳定拒绝原因至少包含记录不完整、工作区忙碌、版本过期、文件冲突、备份失败、数据过期和需要修复，并映射到 §4 的可操作文案。

TurnChangeSet 至少含稳定 id、workspaceId/sessionId/runId/userMessageId、捕获状态与覆盖范围、按路径 before/after 对象及指纹、净统计、Git 来源事实、可撤销原因、版本和过期时间。每次 undo/redo 的操作日志独立保存方向、关联版本、实际 write set、备份、逐文件进度与终态。文件和 diff 分页/按需读取，摘要不夹带全项目内容。

复用现有 files-changed-bar.tsx 的位置，改为每 Run 一条；chat-message-row.tsx 调整归组而不是按有 tools 的每条消息都插入。右侧沿用 review-panel.tsx / Changes 容器和纯 DiffView；本轮内容使用独立数据提供层，不复用 ChangeFileReview 固定的当前 Git 请求语义。新逻辑按职责拆文件，不继续堆大组件或 Host dispatch。

本版不宣称 Pi 原生提供了上述持久变更集服务。[已有调研](../plans/2026-08-30-session-file-rollback-research.md)只作为底层能力背景；其中旧的检查点产品建议不再是本功能的有效范围。实现后同步 PRD、架构及相关 ADR 对“文件撤销”和“对话删除”的区分，本次不提前修改已生效行为文档。

## 9. 交互质量要求

- 使用现有 @piwin/ui-kit Button、Notice、Tabs、Dialog 等公共组件和主题；不因旧组件有原生按钮就继续复制自定义控件。
- 「撤销」「恢复改动」可通过键盘触达，焦点可见；不占用输入框 Cmd/Ctrl+Z，不把全局 Enter 映射成撤销。
- 危险按钮明确但不铺成大型红色警告面板。可逆正常路径不弹确认，这是用户指定的产品决定；异常修复中需要新增覆盖授权的动作才显式确认。
- 成功、失败、记录不完整都同时有文字和语义状态，不只变颜色；读屏通过单一状态区域播报，不抢焦点。
- 文件计数/行数使用稳定排版；按钮 loading 不移动点击目标；长路径可换行/复制，长列表虚拟化，diff 懒加载。
- ui-ux-pro-max 用于错误恢复、原位反馈、渐进展示和键盘焦点检查；没有照搬常规二次确认建议来增加正常路径步骤。本轮仅写 spec，未声称完成视觉或可访问性实测。

## 10. 验收场景

| ID | 场景 | 必须成立 |
| --- | --- | --- |
| TU-A01 | 一次提示词改 4 个文件 | 回答下方只有一条本轮汇总，数量/行数与本轮真实 diff 一致 |
| TU-A02 | 正常点击撤销 | 一次点击生效，不经过检查点列表、预览确认或勾选框 |
| TU-A03 | 执行前已有用户未提交修改 | 撤销后这些修改仍在，不恢复成 HEAD |
| TU-A04 | 更早轮次和无关文件有修改 | 只撤目标轮次，不触碰其他文件和更早贡献 |
| TU-A05 | 新建、删除、修改、二进制、模式变化 | 统计不造假；存在性/内容/模式准确还原，不递归删目录 |
| TU-A06 | 同文件多次编辑后完全改回 | 净统计为零，不显示假文件变化或可执行撤销 |
| TU-A07 | 同一 Run 多次模型/工具调用 | 归为一条汇总，不按助手中间消息产生多个撤销入口 |
| TU-A08 | 失败、中断、工具报错但已写入 | 结算实际变化，数据完整时仍能撤销 |
| TU-A09 | 用户重试和切换回答版本 | run/attempt 对应正确；不自动撤销前次尝试、不切错目标 |
| TU-A10 | 历史轮次文件后被修改 | 整次零写入拒绝；可查看来源/冲突，不自动级联或强制覆盖 |
| TU-A11 | 后续只改不相交文件 | 不把无关文件加入撤销集；满足其他门禁即可撤销 |
| TU-A12 | 撤错了，点击恢复改动 | 原位一键找回该轮变化；聊天、分支、草稿不变 |
| TU-A13 | 撤销后相关文件又变化 | 恢复也拒绝覆盖，不能把 redo 当强制写回 |
| TU-A14 | Shell/外部写入归属不明或捕获缺失 | 不冒充本轮完整贡献，不开放不可靠自动撤销 |
| TU-A15 | 正在运行/后台仍写文件 | 暂不可撤销，有任务出口，不自动停任务或稍后自动执行 |
| TU-A16 | 双击、两客户端提交、断线重连 | 幂等，只执行一次；旧版本目标拒绝，不把超时当成功 |
| TU-A17 | 备份失败、满盘 | 目标文件零写入；解释原因和下一步 |
| TU-A18 | 部分写入后失败/Host 崩溃 | 日志化安全回退或进入可修复状态；不能静默接受新写入 |
| TU-A19 | 相关暂存、冲突、Git 基线漂移 | 拒绝不安全撤销；Git 提交和真实 index 不变 |
| TU-A20 | 重启、源消息删除、记录过期 | 操作状态可找回；有效恢复入口不丢，过期不伪造备份 |
| TU-A21 | SDK/RPC、Desktop/CLI、远程 Host | 同一统计与门禁；没有客户端各算各撤或错误机器写入 |
| TU-A22 | 键盘、窄屏、深浅主题 | 撤销和恢复始终可发现；错误可读、焦点稳定 |
| TU-A23 | 本轮只读或无完整记录 | 零变化与未知分清；不出现伪造的 +1 或本轮精确行数 |
| TU-A24 | 撤销后继续下一轮 | 模型获知文件事实；原回答/测试结果仍标识为历史，不自动重跑 |

实现验证：contracts/all implementers typecheck；变更集合成与安全策略单元/golden tests；Host 并发、持久化、故障注入与重启集成；Desktop 撤销→恢复主链和异常出口 e2e；CLI 与远程同协议验证。按项目规则复用公共 API、更新相关文档、检查源文件行数，不能以“按钮出现了”当作完成。

## 11. 本次审阅边界

请审阅的是：**这轮修改了什么 → 点击撤销这轮 → 必要时恢复这轮**。没有整会话撤销，没有整个目录恢复，没有检查点管理产品。只在无法保证不覆盖其他改动时阻断并说明原因。

审批后再按 contracts → 变更记录/文件事务 → Host → 现有汇总条与详情 → CLI/故障验证实施；目前没有开始功能代码修改。
