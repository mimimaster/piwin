# 长会话上滑短暂白屏

## 症状与原因

长会话上滑时，对话区偶尔短暂空白，停顿或继续滚动后恢复。
代码中虚拟列表仅在 streaming=true 时开启 useFlushSync；已完成会话的
滚动范围更新会等待 React 提交。滚动跨过 overscan 范围后，浏览器的
scrollTop 已变化，而新范围的消息节点尚未挂载，因此可见区域暂时为空。

500 条消息的组件回归测试在 scroll 事件返回前检查可见区节点覆盖：
修复前 idle 分支失败，streaming 分支通过，确认刷新时机存在差异。

## 修复

- idle / streaming 统一同步提交滚动范围更新。
- 保留 ResizeObserver 直接测量、现有高度修复、尾部固定和有界挂载策略。
- 将纯虚拟列表策略从视图组件分离，防止列表组件继续扩张。

## 验证要求

- 500 条消息回归覆盖 idle / streaming，滚动事件内立即检查可见消息。
- 浏览器长历史夹具覆盖连续跨越 overscan 的上滑与到顶。
- 原有首屏、尾部跟随、高度测量、编辑固定和滚动手势测试通过。
- pnpm typecheck 与 Desktop 测试通过。

浏览器夹具不使用真实用户会话，也不启动原生 Tauri；WKWebView 实际手势
下的表现仍需在桌面应用中确认。

  原有首屏断言改为检查所有可见帧稳定，允许加载遮罩下正常测量和调整高度。
