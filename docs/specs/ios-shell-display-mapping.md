# iOS shell display mapping — approved Step 1

## Scope and authority

Baseline: the active Tauri web shell is `apps/mobile/src/inkstone/InkstoneApp.tsx`, not the older `components/navigation` shell. Paths below are relative to `apps/mobile/src/` unless prefixed with `packages/`. This document locks display inputs and follow-up boundaries. The Step 2A candidate below adds readonly structured tool heads and bounded history preservation only; no command, transport, execution or configuration capability is added.

Host remains the sole authority for sessions, tools, runs, projects, settings, review/integration, usage and media. Inkstone formats public contracts; Tauri supplies device adapters. Never import Pi-native details, infer success from tool prose, or promote a cache into Host state. Existing mobile mutation controls are baseline, not authorization to add more.

Labels: **existing** = currently consumed; **gap** = public input exists but active display is incomplete; **not exposed** = required channel/data is absent (not an empty result); **intentionally excluded** = outside this display-only plan. A domain can have more than one label.

Capability rule: gate reads with `HostClient.supportsCommand(command)` against `RemoteCapabilitySummary.allowedCommands`. Omitted ceiling means admitted operator, NOT unsupported; a present list is the exact ceiling. Host still validates admission/payloads. Do not invent feature flags. Existing dedicated flags include `mediaRead`, `trustedTextPreview`, `documentPathResolve`, `flashcardStudy`; backend operation support lives in `SessionBackendCapabilities.operations`. Missing optional fields mean unknown, not false/zero/success.

Required display states for follow-ups: connecting/loading, unsupported (explicit reason), ready-empty, ready-data, error, and disconnected/stale. Attribute Host-owned data to Host + selected session/project; label device preference and cached/snapshot data separately. Unsupported must not remain a spinner. Reconnect/reselection must not silently present old data as current.

## Ownership and safety lock

- **Host:** every ledger/read above, revisions, availability and result/capability decisions. Use opaque project/result/session/media IDs for addressing; paths in `RemoteProjectSummary` are public display metadata, never license to read arbitrary Host files.
- **Device-local:** Inkstone route/face, selection, draft, notification preferences/OS consent, pairing vault and existing Health/voice adapters. Do not display secrets or duplicate Desktop-device-local notification settings.
- **Cache/snapshot:** offline session list `savedAt` and ID/name-only projects; browser JPEG fetch time; mounted read models/tool output promises/log tails. A cache timestamp is not a Host revision/capture timestamp. No settings/MCP/hook/secret cache expansion.
- Existing remote projection/admission/redaction stays in Host. No raw MCP/env/header/hook/secret-reader broadening; no mobile execution/config expansion. Unsafe/missing summary or playback channel is a blocker, not a reason to bypass Host.
