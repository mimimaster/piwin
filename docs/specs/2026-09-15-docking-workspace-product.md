### 核心产品愿景
在单一应用窗口内，支持用户并行推进多会话任务，并按需将关联工具摆放到最适宜的辅助位置；窗口拖动、分屏、折叠与恢复全程保持生产力上下文连续，**不阻断运行、不丢失输入、不串投目标、不误杀资源**。

## 1. 范围界定与交付承诺

### 1.1 首批交付范围（v1 核心承诺）
首批版本严格收敛于高频、高价值场景，包含以下 8 项核心能力：

1. **会话自由组织**：支持从左侧导航栏拖出会话进入工作台；主舞台内的已有窗格支持自由拖拽重排、边缘分屏与中心成组。
2. **有限拓扑约束**：主舞台实行**最多四组（Panes/Groups）的硬上限**，实际可分屏数动态受窗口物理像素制约；右侧工具栏首批保持单一标签组。
3. **首批工具跨区停靠**：**浏览器、代码变更/Diff、文档/画布（Canvas）**三类视图支持在主舞台与右侧工具栏之间双向移动；其余工具保留现有右栏入口与使用方式。
4. **主副会话能力对等**：彻底消除原有主副窗格的功能特权差异，任意位置的会话视图均具备完整的消息交互、模型配置与运行控制能力，移动窗格不降级会话功能。
5. **严密交互反馈**：提供有限几何布局、最小尺寸限制、实时全域落点预览遮罩、随时撤销取消能力，以及全功能的菜单/快捷键非拖拽操作替代路径。
6. **操作语义正交分离**：窗格最大化、全宽展开、收起、关闭、重开与重启恢复均有独立明确的状态语义；不引入无边界的全局布局撤销/重做（Undo/Redo）。
7. **精准身份协同**：严格区分焦点视图、发送目标与工具资源绑定；后台运行与完成提醒基于现有轻量状态推送机制（§9.5），不强依赖后台会话常驻全量实时流。
8. **无损平滑迁移**：读取旧版布局并保留全部会话与工具绑定；旧版 5～8 格布局自动优雅降级为四格展示，旧数据进行全量本地镜像备份以保障版本回退。

### 1.2 阶段规划与演进路径

| 交付批次 | 交付范围 | 与首批的关系与排期准则 |
| :--- | :--- | :--- |
| **第一批 (v1)** | 会话拖拽分屏 + 浏览器 / 变更 / 文档 / 画布跨区停靠 | 独立交付，作为后续功能演进的稳定基座 |
| **第二批** | `TerminalDock` 整体可移动；右侧工具栏支持上下双组 | 拆分为两个独立工程切片分别验收，不阻塞首批发布 |
| **第三批** | 文件树、任务面板、笔记、知识卡片按需逐项开放跨区移动 | 不预先做全量工具改造；以 §11.4 内测数据指标作为排期依据 |
| **暂不排期** | 侧聊跨区停靠、布局撤销/重做、突破四格、增量暂停/补齐协议 | 侧聊继续在右栏使用；隐藏会话按配额管理；待有明确需求后另行立项 |

> [!IMPORTANT]
> **终端生命周期前瞻说明**  
> 第二批终端功能以整个 `TerminalDock` 为最小移动单位，其内部最多 4 个终端会话沿用既有管理面板。首批重构坚决不因“未来要移动终端”而提前改动终端的关闭或退出语义，严防意外引入进程泄露或过早销毁。

**明确排除在近期路线图之外的能力**：
- 拖拽分离为独立 Tauri 原生操作系统窗口或跨屏幕交接。
- 单一工作台混排不同工作区项目（Project Scope）或不同 Host 实例。
- 无限层级嵌套的自由停靠、悬浮浮动窗口、多标签整组批量拖动。
- 将单个终端子标签从 `TerminalDock` 中单独拆离为独立工具窗格。

首批功能在会话拖拽与三类工具跨区能力完备后即可独立发布，无需等待全量工具或右栏双组。本文所述通用规则仅对当前批次已开放的能力生效。

## 2. 空间拓扑与布局规则

### 2.1 三大核心区域职责划分

```text
┌──────────────┬───────────────────────────────────────────────┬────────────────┐
│  左侧导航栏   │                    主舞台                     │   右侧工具栏   │
│  (Left Nav)  │                 (Main Stage)                  │ (Right Panel)  │
│              ├───────────────────────┬───────────────────────┤                │
│  · 项目切换   │ 标签组 1 (Group 1)    │ 标签组 2 (Group 2)    │ 标签组 (Group) │
│  · 会话列表   │ ┌───────────────────┐ │ ┌───────────────────┐ │ ┌────────────┐ │
│              │ │ 会话 / 工具视图   │ │ │ 会话 / 工具视图   │ │ │ 工具视图   │ │
│  [仅拖出源]  │ └───────────────────┘ │ └───────────────────┘ │ └────────────┘ │
│  [不收停靠]  ├───────────────────────┴───────────────────────┤                │
│              │ 主舞台硬上限：最多 4 个标签组                 │ 默认单标签组   │
└──────────────┴───────────────────────────────────────────────┴────────────────┘
```

| 区域名称 | 承载内容 | 拓扑与交互规则 |
| :--- | :--- | :--- |
| **左侧导航栏** | 项目树、会话历史列表 | 作为会话拖拽的**发起源**，绝不作为停靠目标；保持既有虚拟列表与导航逻辑。 |
| **主舞台** | 会话视图、当前批次已开放移动的工具 | **硬上限最多 4 组**；每个窗格为一个独立的标签组（Group），同一时刻激活展示 1 个视图。 |
| **右侧工具栏** | 工具视图（首批支持浏览器/变更/画布移出） | 首批固定为 **1 个标签组**（第二批扩展为最多上下 2 组）；**绝不接收会话视图**；支持整栏展开/收起。 |

- **概念厘清**：
  - **视图（View）**：具体打开的单一会话或特定工具实例。移动视图仅改变呈现拓扑，绝不触发新建会话或克隆工具。同一会话在当前窗口内**有且仅有一个可编辑视图**。
  - **标签组（Group）**：主舞台或右栏中的物理矩形窗格，包含一组有序的标签页。
- **标题栏与标签条呈现**：
  - 组内**仅有 1 个标签**时：隐藏标签条，采用轻量标题栏兼作拖拽把手，保持界面沉浸；
  - 组内**出现 ≥2 个标签**时：自动显示标签条，支持组内拖拽排序与点击切换；
  - 标题栏保留对象名称、状态标识、最大化与更多操作菜单；单标签的关闭按钮仅关闭当前标签，“关闭本组”收敛至下拉菜单中，杜绝误触。

### 2.2 有限布局拓扑规则
主舞台采用严格受控的两层受限树状排布，杜绝无节制的界面碎片化。不论屏幕尺寸多大，**组数硬上限始终为 4**。

主舞台仅允许以下两类拓扑结构：
1. **列式排列（Columnar）**：横向划分为 1～2 个主列，每列可为单一大窗格或纵向划分为上下 2 个窗格。
2. **行式排列（Row-based）**：纵向划分为 1～2 个主行，每行可横向划分为左右若干窗格。
3. **拓扑约束**：每行/每列最多划分 2 个单元，全屏纵横皆不得超过 2 层；严禁出现第 3 层交错复杂嵌套；同向连续分割在计算时优先归并至同一排再执行合规校验。
4. **比例调节**：相邻窗格间的分隔线允许用户自由按比例拖动；不同列之间的横向分隔线不强制全局对齐。

```text
  [单窗]             [双窗·列式]          [三窗·一大两小]            [四窗·四宫格]
┌──────────┐     ┌─────┬─────┐     ┌────────┬────────┐     ┌────────┬────────┐
│          │     │     │     │     │        │        │     │        │        │
│  组 1    │     │ 组1 │ 组2 │     │  组 1  ├────────┤     ├────────┼────────┤
│          │     │     │     │     │        │  组 3  │     │  组 3  │  组 4  │
└──────────┘     └─────┴─────┘     └────────┴────────┘     └────────┴────────┘
```

**布局模板入口**：
菜单中仅提供 4 项基础预设：**单窗、左右双窗、上下双窗、四宫格**。三窗布局由用户拖拽自然生成，不单独设立三窗模板。所有预设动作必须依据当前物理像素动态计算可用性（例如横向空间不足时，纵向分屏依然可能可用），拉大窗口绝不自动创建新窗格。

### 2.3 模板变换与尺寸分配机制

- **局部二分原则**：拖拽至边缘触发拆分时，仅对目标窗格就地一分为二，尺寸微调局限于受影响的排/列带，严禁引发全局强制均分。
- **移出先验计算**：拖拽移动至边缘时，算法先从原拓扑中虚拟移出该视图，再模拟目标分割；严禁因移出前已达 4 格上限而误拦截合法的移动操作。
- **非法拓扑熔断**：若目标分割将突破 4 格或破坏两层拓扑结构，立即禁用该边缘落点；**严禁未经用户许可自动重组整个工作台结构**。
- **模板收缩与扩展**：
  - 应用更少组数的模板时，保留组按视觉顺序对应分配，多余组内的所有标签自动追加至最后一个保留组末尾，去重并保留相对顺序，当前活动视图保持激活；
  - 应用更多组数的模板时，新组作为空组建立，等待填入视图；非用户显式操作绝不自发产生空组。
- **临时状态与恢复**：用户手动合并为单组后，再选双窗不会凭空恢复历史分组；临时最大化或因窄屏导致的临时聚焦展示，在恢复时必须无损还原原有分组与尺寸比例。
- **空组自愈**：因关闭或移出导致的空窗格自动消除，相邻窗格自然伸展；主舞台所有视图均关闭时，保留一个居中的空舞台占位引导页。
- **权重与渲染分离**：用户拖动保存的行列比例权重与实际物理渲染尺寸完全解耦；嵌套分隔条基于子树最小安全尺寸动态计算边界，不硬性套用全局 20%～80% 限制。

### 2.4 容量配额与运行预算

| 管控对象 | v1 规格上限 | 达限处理策略 |
| :--- | :--- | :--- |
| **主舞台窗格组数** | **硬上限 4 组**（且须满足物理像素下限） | 仍允许组内成组、位置交换与移动；禁止新增分割窗格 |
| **右栏可见组数** | **首批 1 组**（第二批最多 2 组） | 允许将工具加入当前组作为标签；禁止创建新组 |
| **单 Workspace 打开视图总数** | **上限 24 个**（含隐藏标签与有效草稿） | 拦截新建操作并主动弹窗打开视图列表管理器，引导用户批量清理；严禁静默淘汰关闭已有视图 |
| **全量实时订阅会话数** | **上限 8 路**（沿用通信协议硬限制） | 动态配额分配：可见会话 > 可见工具依赖会话 > MRU 隐藏会话；详见 §9.5 |
| **本机终端进程数** | 沿用现有；第二批明确为**单窗口池最多 4 个** | 首批不扩容；第二批跨项目全局计数，切换项目不重置计数 |
| **交互式浏览器工具** | **每 Host、每窗口最多 1 个** | 重复打开自动聚焦既有视图；浏览器内部多标签正常工作 |
| **常驻保活画布视图** | **每窗口最多 4 个**（跨项目计数） | 达到上限后弹窗提示用户显式关闭已有画布，绝不静默重载覆盖 |

## 3. 交互模型与拖拽矩阵

### 3.1 拖拽发起源规范
- **左侧会话行**：仅限点击标题文本或专用把手区域触发拖拽；展开箭头、上下文菜单按钮、重命名输入框绝不触发拖拽。
- **主舞台与右栏窗格**：单标签时通过标题栏把手拖拽；多标签时拖拽具体标签项。
- **跨区工具限制**：仅首批开放跨区的工具（浏览器、变更、画布）显示跨区移动把手；未开放工具在组内支持标签排序，但不展示跨区把手。
- **原生拖拽规避**：所有工作台内部拖拽把手均须显式声明退出 Tauri 原生窗口拖动区域（`data-tauri-drag-region="false"`），仅保留窗口全局顶层空白区域用于移动原生窗口。
- **操作原子性**：首版每次仅允许拖动单个视图；多标签组的空白标题区域不作为“移动整组”的把手。

### 3.2 停靠判定与落点决策矩阵

| 拖拽来源 | 释放目标位置 | 最终处理结果 |
| :--- | :--- | :--- |
| **未打开的会话** | 主舞台窗格边缘 | 实例化新视图 + 目标窗格就地拆分 |
| **已打开的会话** | 主舞台窗格边缘 | 原位移出该视图 + 目标窗格就地拆分 |
| **未打开的会话** | 主舞台窗格中心 / 标签条 | 切换该窗格当前会话，不追加标签；若该会话已在其他窗格打开则聚焦已有视图 |
| **已开放跨区工具** | 主舞台窗格边缘 | 移出该工具视图 + 目标窗格就地拆分 |
| **已开放跨区工具** | 主舞台窗格中心 / 标签条 | 追加进入目标标签组并激活 |
| **已开放跨区工具** | 右栏中心 / 标签条 | 首批归并入唯一工具组；第二批支持选择上/下组 |
| **工具视图** | 右栏上/下边缘 | 首批不响应分组；第二批支持拆分为双组（已有双组则禁用） |
| **已开放跨区工具** | 右栏收起时的窗口右边缘停靠带 | 展现右栏临时展开预览，成功释放后展开右栏并停靠 |
| **会话视图** | **右侧工具栏任意位置** | **严格拒绝**，气泡提示：“会话请放置于主工作区” |
| **任意视图** | 自身窗格中心 | 无操作（No-op）；标签条支持组内左右排序 |
| **组内当前活动标签** | 自身窗格边缘 | 组内有其他标签时拆出独立成窗；为唯一标签时无操作 |
| **会话 / 开放工具** | 空白舞台或空组中心 | 直接填入该占位，不产生冗余空组 |
| **外部文件 / 图片 / 文本** | 输入框 / 正文编辑器 | 沿用现有附件上传、路径插入与文本输入流，绝不触发工作台拓扑变动 |

> [!NOTE]
> **窗格组交换语义**  
> “交换位置”作为菜单动作提供：允许用户选取两个窗格，整体对调其包含的全部标签与状态，内部活动项与上下文保持不变。跨区交换必须在两个窗格内所有工具均支持跨区时方可执行；若包含会话或未开放工具则显式禁用，严禁通过交换绕过批次边界。

### 3.3 拖拽生命周期与反馈规范

```text
[拖拽发起] ──> 显示轻量浮层 + 来源原位占位 (不卸载组件)
     │
[悬停移动] ──> 边缘触发带检测 (短边 20%, ≤72px)
     │          ├── 命中合法目标：显示半透明高亮遮罩 + 语义文案 ("在右侧分屏")
     │          └── 命中非法目标：禁止高亮 + 显式短原因提示 (如 "最多四格")
     │
[释放提交] ──> 校验尺寸与拓扑 ──┬─ 通过 ─> 原子提交 LayoutState ──> 聚焦新视图
     │                          └─ 失败 ─> 撤销变动 + 恢复原状 + 提示原因
     │
[异常中断] ──> 按 Esc / 窗口失焦 / 目标失效 ──> 立即取消，瞬时复原，无副作用
```

1. **发起阶段**：指针拖拽位移超过阈值时启动，展示包含图标与标题的轻量半透明镜像；来源窗格保留半透明占位框架，**严禁卸载或重置底层内容**。
2. **悬停判定**：
   - **命中优先级**：标签条区域 > 窗格四周边缘判定带 > 窗格中心区域。
   - **边缘带计算**：初始设定为窗格短边的 20%，绝对值最大不超过 `72px`；四角死角依据归一化几何距离决出最近边；平局时优先沿用上一有效方向，首次平局水平方向优先。
3. **预览保真度**：预览遮罩必须精准体现“来源窗格移出收拢”与“目标窗格挤压拆分”后的最终几何构型，严禁只展示局部遮罩而在释放时发生突兀跳跃。
4. **释放与事务提交**：释放瞬间基于最新视口物理尺寸执行终审校验；通过后在单一事务内同时提交主舞台与右栏的新拓扑结构，并将键盘焦点赋予该视图；输入框保留已有文本选区，绝不自动触发提交发送。
5. **安全取消机制**：用户按 `Esc`、窗口失焦、拖出窗口外松手、源会话被删除或项目切换时，拖拽事务无条件取消，布局瞬间回滚至初始状态。
6. **显式非法反馈**：
   - 非法操作提供短文案提示：`空间不足`、`已达四格上限`、`跨项目无法直接放置`、`不支持该排列`、`该工具暂不支持放入主工作区`。
   - **防误解保障**：未开放工具在右栏内部拖动悬停至主舞台时，**必须明确显示“该工具暂不支持放到主工作区”**，严禁静默吞没导致用户误判为拖拽机制失效。
7. **跨项目拖拽引导**：拖拽另一项目的会话至当前工作台时，释放被拦截，但系统弹出保留约 4 秒的操作气泡：`该会话属于项目 [B] · 点击切换到该项目`。点击后触发合法项目切换流，悬停绝不触发切换。
8. **右侧停靠带瞬态响应**：右栏收起时，仅在合规工具拖动至屏幕右边缘时才呈现感应停靠带；若当前窗口宽度不足以容纳右栏展开，则预览展示为抽屉（Drawer）覆盖层，松手确认停靠前绝不永久展开侧栏。

## 4. 焦点状态与展示模式

### 4.1 侧栏点击规则与单组呈现（默认态保障）

- **点击会话**：切换当前工作台会话。未分屏时主舞台始终只有这一路对话，不追加标签、不堆标签条。
- **点击已在分屏中打开的会话**：激活它所在的窗格，不新增标签。
- **跨项目会话点击**：触发标准项目切换流程，持久化当前项目状态后，切换至目标项目并恢复其独立的工作台布局。
- **侧栏指示标识**：侧栏高亮明确指示当前绑定的**会话目标（Session Target）**。

```text
单组默认态（1 个会话）
┌──────────────────────────────┐
│                              │
│ 无标签栏，与传统单窗完全一致 │
│ 侧栏点击 = 切换当前会话      │
│                              │
└──────────────────────────────┘
```

> [!IMPORTANT]
> **侧栏不是浏览器标签栏**  
> 点击侧栏会话只切换当前对话。未分屏时若磁盘里还留着多会话标签，同步时收拢回当前工作台会话，不把标签条当成默认形态。分屏仍由拖拽 / 分屏操作产生，不由侧栏点击产生。

### 4.2 三重正交身份体系

为彻底根绝“输入串投”与“副窗格特权缺失”问题，系统确立严格正交的三重身份管理模型：

1. **焦点视图（Focused View）**：当前物理接收键盘敲击与输入事件的视图。
2. **会话目标（Session Target）**：当前逻辑绑定的交互会话；当焦点移动至非会话视图（如右栏工具、代码查看器）时，**会话目标保持锁定不变**。若用户聚焦于尚未发话的空会话草稿，该草稿即作为独立的会话目标，绝不回退至旧会话。
3. **工具资源绑定（Tool Binding）**：工具视图内部实际挂接的项目路径、分支、会话 ID、文件或浏览器上下文。

- **失效保护**：若当前会话目标被关闭或删除，系统**严禁自动转移至另一会话盲发**；所有工具回填按钮状态转为“选择接收会话”。
- **快照捕获**：所有异步操作（如 Agent 生成预览、命令执行）在触发起点瞬时锁定会话目标，返回时严禁重新读取当前的实时焦点。

### 4.3 展示模式状态机

工作台顶层展示状态采用**单一互斥状态机**，严禁使用多个独立布尔变量叠加：

```text
             ┌───────────────────────────────────┐
             │       常规布局 (Normal Layout)    │
             │       最多四格，标准分屏呈现      │
             └──────┬─────────────────────▲──────┘
                    │                     │
           触发最大化│                     │ 退出最大化 / Esc
                    ▼                     │
             ┌────────────────────────────┴──────┐
             │       窗格最大化 (Maximized)      │
             │       目标组全屏，其余窗格就地隐藏 │
             └──────┬─────────────────────▲──────┘
                    │                     │
           右栏临时展开│                     │ 关闭右栏展开
                    ▼                     │
             ┌────────────────────────────┴──────┐
             │    右工具区展开 (Tool Expanded)   │
             │    (原右栏全宽模式，纯临时放大查看) │
             └───────────────────────────────────┘
```

- **状态流转规则**：
  - 在窗格 A 最大化状态下显式切换至窗格 B：B 所在组自动成为新的最大化视图；退出最大化精准恢复原布局。
  - 右栏全宽展开时在主舞台点击会话：退出全宽状态并平滑切回目标会话。
  - 模态弹窗或菜单关闭后，焦点自动交还原发起视图；若原视图已关闭，则回退至最近的可见窗格。
  - **右栏全宽的正名与约束**：现有“右栏全宽”在 v1 中正式定义为“右工具区临时展开”；仅供临时聚焦审查，**不改变基础拓扑结构、不写入持久化存储**。菜单明确区分为“临时展开”与“移至主工作区”。
- **标签关闭后的焦点回退**：关闭当前标签时，优先激活同组右侧标签；若右侧无标签则激活左侧标签；若整组关闭，焦点转移至空间距离最近的活跃窗格。此回退仅决定键盘聚焦，绝不授权向新窗格静默发送数据。

### 4.4 辅助交互与快捷键规范

- **右键上下文菜单**：所有标签提供统一的菜单动作：`向左/向右/向上/向下移动分屏`、`移动至已有组`、`返回工具栏（仅工具）`、`交换窗格位置`、`最大化/恢复`、`关闭当前标签`。对当前布局非法的选项置灰并注明原因。
- **标准快捷键映射**：
  - 分屏：macOS `⌘D`（水平分屏）、`⇧⌘D`（垂直分屏）；Windows `Ctrl+D` / `Ctrl+Shift+D`。
  - 焦点切换：`⌥⌘ + 方向键`（macOS）；`Alt+Ctrl + 方向键`（Windows）。
  - 最大化切换：`⇧⌘Enter`（macOS）；`Ctrl+Shift+Enter`（Windows）。
  - 关闭活动视图：`⌥⌘W`（macOS）；`Ctrl+Alt+W`（Windows）；**保留原生 `⌘W` 为关闭原生窗口语义**。
  - 重开已关闭视图：`⇧⌘T`（macOS）；`Ctrl+Shift+T`（Windows）。
- **按键防冲突机制**：`Esc` 键按优先级严格执行：优先取消当前正在进行的拖拽；其次关闭当前浮层/退出最大化展示；**绝对严禁向底层透传为终止 Agent 运行信号**。

## 5. 工具上下文与会话协同

### 5.1 工具实例语义与绑定规则
首批仅开放浏览器、代码变更、文档/画布三类工具进入主舞台，其余工具保留在右栏，但所有工具必须明确会话绑定规则，避免多会话并行时的上下文混乱。

| 工具名称 | 实例单例/多实例属性 | 上下文绑定规范 | 标题状态栏呈现 |
| :--- | :--- | :--- | :--- |
| **文件树** | 当前项目全局单例 | 严格绑定项目根路径，保留折叠/展开与滚动位 | 项目名称 |
| **代码变更/Diff** | 支持按仓库/worktree 多实例 | 绑定特定工作区或版本对比，切会话不换工作路径 | `固定: 仓库/工作树标识` |
| **任务面板** | 首批右栏单例（第三批支持多实例） | 动态跟随当前活跃的会话目标 | `跟随: 会话名称` |
| **侧聊 (Side Chat)** | 依附于父会话（暂不开放跨区） | 创建时锁定所属父会话，移动或切焦点不改变归属 | `固定: 父会话名称` |
| **复杂文档** | 资源级多实例 | 强绑定具体项目文件，重复打开精准定位已有视图 | `固定: 文件相对路径` |
| **画布 (Canvas)** | 资源级多实例 | 绑定 Session + Message + Artifact 唯一坐标，流式原地刷新 | `固定: 画布组件标题` |
| **终端 (Terminal)** | 窗口级单例（第二批开放跨区） | 整体可移动，内部 4 个 PTY 保持独立 cwd，注明“本机” | `本机终端 [4/4]` |
| **交互浏览器** | 每 Host、每窗口单例 | 共享浏览器实例与控制租约，明确呈现控制权归属 | `共享浏览器 · 控制中` |
| **笔记 / 卡片** | 项目集合单例（第三批开放） | 复用既有集合存储，绝不借机派生平行编辑器 | `项目笔记 / 知识集` |

- **快速定位与归位**：工具箱入口对已移至主舞台的工具打上位置标签（如 `主工作区·组2`）；再次点击直接跳转激活该视图，绝不创建副本。位于主舞台的工具标题菜单中统一提供“返回工具栏”操作。
- **跟随模式约束**：标题栏严格显示 `固定: [目标]` 或 `跟随: [目标]`。仅任务面板等原生具备跟随能力的工具提供切换开关，侧聊、文档与终端严禁提供模棱两可的“跟随当前会话”。

### 5.2 从工具向会话回填内容规范
- **明确投递目标**：文件添加、路径插入、浏览器拾取元素、画布改动提案等回填交互，其触发按钮旁必须明文展示接收端会话名称；空间受限时在悬浮 Tooltip 或菜单中展示完整名称。
- **主舞台输入隔离**：当主舞台同时展示多个会话时，消息发送、中断停止与模型参数调节**只能在各会话窗格内独立的 Composer 区域发起**。
- **进入草稿缓冲**：工具回填的内容默认仅置入目标会话的输入草稿区；仅当用户明确点击“直接发送”时方可触发执行。
- **目标失效兜底**：若在工具生成内容期间目标会话被关闭或删除，生成结果在工具端完整保留，界面弹出“会话已关闭，请重新选择接收目标”的选择器，严禁静默丢弃。
- **草稿会话处理**：向未绑定实际 Host 会话的空白草稿回填内容时，不自动向 Host 预建会话，严格遵循用户首次发话时再建会话的既有生命周期。

### 5.3 Agent 触发的自动展现策略
- **用户显式操作**：用户点击文件链接或工具按钮，系统立即打开或定位目标视图并赋予焦点。
- **Agent 生成预览产物**：自动生成的新代码预览或画布，以新增标签的形式静默追加至右栏默认工具组，并通过气泡轻量提示，**绝对严禁强行抢夺用户当前的输入焦点**；若对应资源已打开，则在原位静默流式刷新。
- **配额满载处理**：当打开视图已达 24 个上限时，会话消息流内保留产物打开卡片，但不自动在侧边栏或舞台新增标签页。
- **已跨区视图就地更新**：若对应工具视图已被用户拖动至主舞台，后续所有自动更新直接定向至该舞台视图，绝不在右侧工具栏重新创建冗余副本。

## 6. 资源生命周期与操作语义

### 6.1 核心操作的生命周期对照矩阵

| 操作场景 | 会话与草稿 (Session / Draft) | 本机终端 (Terminal·第二批) | 交互浏览器与画布 (Browser / Canvas) |
| :--- | :--- | :--- | :--- |
| **拖拽移动 / 分屏 / 成组** | 状态完全保持，附件不丢失，滚动位锁定 | PID/PTY/xterm 实例不变，仅触发视口尺寸 resize | 租约/页面/iframe 节点保持，不重载页面 |
| **切换标签 / 最大化 / 右栏折叠** | 内容保活；按 §9.5 预算维持实时订阅 | 进程持续后台运行，尺寸为 0 时暂停 resize | 控制器保活；隐藏渲染减负，不销毁底层资源 |
| **显式关闭视图 (Close View)** | 后台 Run 继续推进，草稿保留，可在历史找回 | 隐藏前端视图，终端管理器保持后台进程存活 | 浏览器释放本视图租约；画布销毁当前 DOM 节点 |
| **显式终止进程 (Kill/Exit)** | 不受影响 | 显式杀死对应 PTY 进程，释放物理配额 | 不受影响 |
| **切换工作区项目 (Switch Project)** | 保存当前布局与草稿，挂载新项目数据 | 共享资源池持续运行，保留 cwd，不自动 cd | 窗口级资源保持，避免并发挂载冲突 |
| **退出应用 / 关闭窗口** | 遵循既有 Host 生命周期，不因布局引发 abort | 依规安全终止本窗口归属的所有终端进程 | 释放本窗口浏览器租约，销毁画布全部临时状态 |

### 6.2 销毁、未保存检查与退出确认
- **第二批终端关闭语义**：关闭 `TerminalDock` 仅代表隐藏视图，工具菜单将显示 `终端 (N 个正在运行)`，点击可随时唤回；用户若要销毁进程，必须在终端内部输入 `exit` 或在管理面板点击“终止终端”。
- **可编辑内容关闭保护**：关闭文档、笔记等工具视图时，严格触发未保存变更检查（提示：保存 / 放弃 / 取消）；保存失败时强行保持视图开启。执行“关闭整组”时，先串行完成组内所有视图的保存校验，任意一项取消则中止整组关闭。
- **第二批退出防丢提示**：退出原生应用或关闭窗口时，若当前窗口仍有运行中的终端进程，弹出阻塞式对话框确认：`仍有 N 个终端进程正在运行，退出将强制终止：[确定退出并终止] / [取消]`。
- **DOM 重载铁律**：重开已关闭的画布或浏览器允许重新加载；但在工作台内的**拖拽移动、分屏、成组与临时隐藏，绝对严禁触发组件重载或网络刷新**。

## 7. 几何预算与自适应降级

### 7.1 像素几何预算基准
系统以真实物理像素（CSS px）为硬性约束，在窗口整体可用空间中扣除导航栏、边框、分隔条及外围内边距后，基于以下基准执行统一校验：

| 视图类型 | 最小安全尺寸 (宽 × 高 px) | 边界约束与排版说明 |
| :--- | :--- | :--- |
| **主舞台会话视图** | **420 × 320** | **必须保障完整 Composer 正常排布**；输入区支持内部独立纵向滚动 |
| **主舞台常规工具** | **320 × 220** | 通用工具最小下限；具体工具若有更大要求则优先采用特定下限 |
| **浏览器 / 画布视图** | **360 × 260** | 核心工具栏控件（地址栏、缩放、回退）始终外露不可截断 |
| **右栏文件树 / 任务** | **240 × 200** | 初始基准线；切片 A 若实测 200px 体验合规可调整，分隔条尺寸另算 |
| **右栏终端 / 复杂文档** | **320 × 220** 起 | 超宽内容必须通过工具内部滚动条承载，严禁强行撑破侧栏 |

> [!NOTE]
> **尺寸规格调整依据**  
> 主舞台会话最小宽度由此前旧版的 300px 显著提升至 420px，以确保复杂的输入框（含模型切换、附件栏、知识库选择及发送按钮）不发生挤压变形。一个标签组的最小安全尺寸取组内所有已打开视图所需尺寸的最大值。

**标准窗口验证矩阵**（研发切片 A 必须覆盖实测）：
1. `1280 × 800`（小屏笔电极限）：右栏收起时允许左右双窗；右栏展开时仅允许单会话。
2. `1440 × 900`（主流轻薄本）：右栏展开下允许左右双窗。
3. `1512 × 982`（MacBook Pro 14"）：右栏展开下允许三窗稳定排布。
4. `1920 × 1080`（主流外接桌面大屏）：允许四宫格全量稳定展开。

### 7.2 确定性自适应降级序列

当用户调整窗口尺寸导致物理可用面积跌破最小安全线时，系统启动**确定性自适应降级**，严禁篡改底层拓扑树：

```text
[空间充足] ──> 正常呈现多窗分屏 (按用户设定比例)
     │
[窗口变窄] ──> 1. 新增分屏拦截：禁用边缘分屏，仅允许“加入标签组”
     │
[继续变窄] ──> 2. 右栏抽屉化：右栏展开不再挤压主舞台，改为半透明抽屉层浮动覆盖
     │
[严重不足] ──> 3. 聚焦展示模式 (Focused View)：主舞台仅渲染当前活动组，
     │          标题栏呈现“其它 N 组 ∨”快速切换器；拓扑树在内存完整保留
     │
[窗口拉大] ──> 4. 迟滞安全恢复：当视口宽度超过 (原布局最小尺寸 + 32px) 时，
                自动退出聚焦模式，无缝还原原有多窗拓扑与尺寸比例
```

- **移动端与极窄窗**：在移动端或极端小窗下，默认进入聚焦模式，仅渲染单个活动组与底部抽屉式工具栏。
- **窄屏操作限制**：在聚焦展示模式下，禁止用户通过拖拽重构布局，仅允许标签切换、关闭与组内追加，防止用户盲目破坏不可见的后台窗格。

## 8. 状态持久化、恢复与重开

### 8.1 本地存储模型与保存边界

```text
~/.piwin/workspaces/
└── [HostID]__[ProjectScope]__[WindowID]__v2.json  <── 布局拓扑、窗格权重、标签归属
└── drafts/
    └── [HostID]__[SessionID].json                 <── 独立防抖持久化 (500ms)，含草稿与附件引用
```

- **存储隔离 Key**：采用强确定性主键：`Host ID + Project Scope + Logical Window ID + Schema Version`；主窗口 ID 保持全局稳定，严禁每次启动随机生成。
- **序列化范围**：仅保存结构拓扑树、窗格层级比例、各组包含的视图描述符（View Descriptors）、各组活动项 ID、用户调整的右栏标准宽度。
- **瞬态不落盘**：窗格临时最大化、右栏全宽临时展开、窄屏聚焦展示等瞬态，**一律不写入持久化存储**；重启后统一按标准布局或依据视口自适应呈现。
- **草稿安全机制**：
  - 会话草稿与附件引用与布局解耦，独立按会话落盘，采用 `500ms` 强防抖；在切换会话、关闭窗格或窗口失焦时立即执行主动同步（Flush）。
  - 应用运行期内，窗格拖拽、移动绝不丢失未落盘的 `File` 对象；系统重启后若底层物理缓存失效，原位展示“需重新选择附件”的友好占位符，绝不伪造可发送状态。

### 8.2 启动恢复与重连逻辑
- **拓扑先验校验**：启动时优先反序列化结构树，并逐项验证视图对应资源的有效性；若会话已被物理删除，该位置渲染带提示的占位卡片并提供“移除视图”按钮，**绝对严禁静默改绑为其他无关会话**。
- **终端断点隔离**：布局树中绝不序列化瞬态 PTY 进程 ID；重启后终端窗格展示“重新打开终端”指引卡片并自动恢复原工作路径（cwd），绝不自动盲目重放 Shell 历史命令。
- **Host 离线容灾**：当远程 Host 处于离线状态时，本地工作台布局与历史消息草稿依然完整可读；网络恢复后通过数据代际计数器（Generation Counter）安全对齐，阻断过期异步响应写坏新状态。

### 8.3 最近关闭视图的重开机制（Reopen History）
- **轻量关闭栈**：每个 Workspace 在内存中维护一份容量为 **20 项**的最近关闭视图记录栈（LIFO），支持通过快捷键（macOS `⇧⌘T` / Windows `Ctrl+Shift+T`）或菜单逐级唤回；该栈仅记录“视图是谁”，不记录拓扑几何变动。
- **重开落点仲裁**：
  - 若原窗格依然存在：优先重开并追加至原窗格末尾；
  - 若原窗格已销毁：会话视图默认追加至当前主舞台活跃组；工具视图自动归位至右侧工具栏；**绝不为了重开一个标签而强行重建已消除的分屏**。
- **重开校验**：若目标资源已在工作台中打开，触发操作仅平滑跳转聚焦已有视图，严禁创建副本。
- **恢复默认布局**：工作台提供“恢复默认布局”指令，将所有打开的会话合并回主舞台单组，工具全数撤回右侧工具栏，原位保留所有草稿与内容。

## 9. 工程架构与运行时设计

### 9.1 技术选型与实施原则
- **拖拽引擎选型**：采用 Atlassian `@atlaskit/pragmatic-drag-and-drop`（轻量、无头、对复杂 WebView 及 iframe 穿透友好）结合自主研发的受限拓扑策略引擎。
- **严禁双轨制**：v1 一旦实施，彻底废弃原有的“单主窗格 + 附窗格”过渡代码，不保留两套可写布局引擎。
- **核心前置实证**：在进入切片 B 之前，必须在真实 Tauri WebView 环境下完成首批切片 A 验证：会话、镜像浏览器、交互画布跨区往返 20 次，验证 DOM 状态、输入框草稿及滚动位保持无损。

### 9.2 核心模块职责划分

| 核心模块 | 专属职责边界 | 归属工程层次 |
| :--- | :--- | :--- |

| **ViewRegistry / Storage** | 全局唯一稳定 `viewId` 分配、跨区归属、视图元数据、最近关闭栈与持久化存储 | `apps/desktop/src/workbench/views` |
| **SessionViewController** | 单会话消息加载、草稿管理、模型参数、执行动作分发；主副窗格共用同一控制器 | 优先复用 `@piwin/host-client` 与公共组件 |

| **WorkspaceSurface** | 稳定 DOM 挂载宿主、位置几何投影、指示器、落点预览遮罩与无障碍焦点管理 | `apps/desktop` + `@piwin/ui-kit` 组件 |

- **树叶节点重构**：布局树叶子节点由旧版直接绑定 `sessionId` 彻底重构为持有 `groupId`；每个 `Group` 维护有序的 `viewIds` 数组与当前的 `activeViewId`；`View` 独立保存资源类型与上下文描述符。
- **全域单一事务**：主舞台与右侧工具栏的状态整合至统一的 `WorkspaceState` 中同步提交，彻底终结右栏独立维护 `openTabs` 导致的跨区时序竞争。

### 9.3 稳定挂载与资源宿主（Anti-Reparenting）

> [!CAUTION]
> **绝对规避 React DOM 重挂载**  
> React 在组件跨父级节点移动时会默认触发卸载重挂（Unmount & Remount），导致 WebGL 画布上下文丢失、iframe 页面重新刷新、输入法 IME 状态断裂。

- **宿主挂载策略**：首批主舞台会话及开放工具统一挂载于顶层**平面稳定宿主层（Surface Layer）**，以稳定唯一的 `viewId` 作为 React Key；当窗格位置变动时，仅通过 CSS Transform 或绝对定位修改外围宿主几何坐标，**底层的真实 DOM 树绝不重建**。
- **Chrome 与 Content 解耦**：外围的标题栏、标签条随布局树组件正常渲染刷新；内部的具体会话正文与工具内容与外围容器完全解耦。
- **终端与浏览器隔离**：浏览器租约独立于前端面板挂载，位置移动不丢失控制权；第二批终端彻底剥离组件卸载时附带的 `close-all` 破坏性逻辑，由独立的全局资源注册表管理。
- **iframe 沙箱严控**：拖拽过程中的全局事件遮罩层用于捕获鼠标移动，底层代码沙箱（Sandbox）CSP 规则保持恒定不变。

### 9.4 原子拖拽事务流水线
一次合法的视图放下操作严格遵循以下六步流水线，中途任何一步校验不通过，整体事务立即回滚：

```text
[1. 快照捕获] 锁定当前源 sourceId、所在 scope、当前修订版本号 revision
     │
[2. 候选生成] 内存生成虚拟候选拓扑：源位置收拢 -> 重新平衡 -> 目标位置虚拟拆分
     │
[3. 规则预检] 校验工具开放范围 -> 校验主舞台最多四格 -> 校验是否符合两层拓扑
     │
[4. 几何终审] 读取物理视口尺寸，校验目标拆分是否满足 420x320 等最小安全像素
     │
[5. 原子提交] 在单一 React / 状态机事务中同时更新主舞台与右栏拓扑，赋予新视图焦点
     │
[6. 异步落盘] 触发 500ms 去抖本地持久化存储写入
```

### 9.5 实时订阅预算与边界控制

> [!IMPORTANT]
> **无新协议依赖原则**  
> 首批 v1 版本的落地**绝对严禁引入新的 Host 暂停/补齐协议**，发布不以 Host 协议改造为前置条件。

- **8 路实时连接预算分配法则**：
  受既有通信通道最多 8 路实时会话的物理硬约束，系统按以下优先级动态分配实时流：
  1. **主舞台当前可视的会话**（最多 4 路）；
  2. **右栏当前可视工具依赖的源会话**（最多 1 路）；
  3. **最近使用的隐藏会话标签（MRU Hidden Tabs）**（分配剩余约 3～4 路预算）。
- **预算内隐藏会话**：保持挂载与全量实时流推送，切回时零延迟即时可用。
- **预算外隐藏会话**：
  - 自动卸载其前端重型控制器，仅保留底层 `DraftStore` 输入草稿与最后滚动高度；后台 Agent Run 依然在 Host 正常执行，不受任何影响。
  - 切回该标签时，复用与现有“在侧栏点击会话”完全一致的标准 Resume 逻辑：拉取有界历史页、快速对齐最新 Run 状态；界面仅展示标准轻量加载态，**严禁引入破坏性的“正在同步禁止发话”阻塞模态**。
- **侧栏与折叠菜单的全局状态**：
  侧栏小红点及“更多 N”折叠菜单中的运行中/完成状态，统一源自既有的轻量状态推送服务（如 `backendServiceSessionIds`），绝不依赖长连全量消息流维持。

## 10. 旧版数据迁移与发布策略

### 10.1 Schema 迁移与拓扑降级算法

1. **版本识别与备份**：读取旧版 `schema v1` 布局配置；在执行任何解析前，将原始记录原样备份为 `...v1.backup.json`，确保版本可随时回退。
2. **合法四格拓扑映射**：旧版配置中完全符合新两层规则且 `<= 4` 组的布局，按叶子节点无损转换为 `v2` 分组模型，精准继承原有窗格比例与活动视图。
3. **5～8 格布局确定性降级**：
   - 提取原可视顺序中的前 3 个窗格，分别映射至新四宫格的前 3 个独立组；
   - **将原第 4 至第 8 组的所有会话，全部汇聚归并入新四宫格的第 4 组中，转化为并列标签页**；
   - 默认激活第 4 组中原本处于活动状态的会话；
   - 迁移成功后弹出一次性非阻断轻量通知：`工作台已升级为最多四格，原其余 N 个会话已收纳至第 4 组的标签页中`，附带一键直达指引；提示支持关闭且不再重复出现。
4. **异常数据自愈**：遇到结构损坏或无法识别的会话 ID 时，提取可识别视图放入默认单组中，损坏条目渲染为“无效视图”占位卡片供用户手动清除，**绝对严禁静默格式化为空白工作台**。

### 10.2 渐进发布与升级引导
- **Feature Flag 绝对隔离**：开发与内部测试期间采用单一 Feature Flag 切换新旧工作台，严禁新旧两套代码同时监听或向持久化层写入数据。
- **初次升级友好引导**：用户首次升级进入新工作台时，界面底部展示轻量级气泡引导条：`全新工作台支持拖动会话，以及浏览器、变更和文档；拖至中心成组，拖至边缘分屏`。不强制遮罩新手教程，用户点击关闭后永不再弹。

### 11.2 关键硬性验收门禁（Checklist）

- [ ] **多会话并行无干扰**：双会话同时高速流式输出，任意拖动窗格、成组、切换焦点，发话、打断、模型切换与权限确认均精准指向目标会话。
- [ ] **消除副窗格特权差异**：副窗格拥有主窗格全部能力，不支持的功能严格受限于 Scope 或 Host Capability，绝不因处于副窗格而降级。
- [ ] **草稿与输入绝对保全**：窗格移动、多标签切换、分屏重排过程中，输入框未发送的文本、上传中的 File 对象、图片引用及滚动高度无损保持；重启应用后丢失的物理附件有显式恢复指引。
- [ ] **比例恢复不变形**：设置 `70% / 30%` 比例后拉窄窗口触发聚焦展示，再拉大窗口，几何比例精准还原为 `70% / 30%`；展开右栏绝不强行挤爆主舞台。
- [ ] **最大化逻辑自洽**：窗格 A 最大化时在侧栏点击会话 B，B 所在窗格成为新的唯一最大化视图；按 `Esc` 退出最大化平滑恢复多窗；`Esc` 绝不误杀 Agent 运行。
- [ ] **有限模板严守约束**：布局模板仅提供单窗、左右、上下、四宫格；三窗只能由拖拽自然生成；减少组数绝对不丢标签；主舞台硬上限坚决锁死 4 格，拉大窗口绝不自发新建第 5 格。
- [ ] **首批工具跨区无损**：浏览器、交互画布、变更查看器往返主舞台与右栏移动 20 次，页面租约未断开、画布 WebGL/JS 临时状态未丢失、文档阅读位置不漂移、终端后台进程不受干扰。
- [ ] **最近关闭重开有效**：通过 `⇧⌘T` 或菜单能精准重开最近关闭的视图；若原窗格已不存在，智能降级至当前活动组或右栏，绝不克隆重复视图，绝不自动重放危险命令。
- [ ] **未开放工具防穿透与友好反馈**：未开放跨区的工具绝不暴露跨区把手与菜单项，且不能通过组交换绕过限制；在右栏内拖拽未开放工具悬停至主舞台时，**必须明确展示“该工具暂不支持放到主工作区”**。
- [ ] **跨项目引导可操作**：跨项目拖拽会话被拒绝后，提示气泡必须附带“切换到该项目”按钮，点击后平滑跳转项目并恢复目标工作台布局。
- [ ] **单组默认体验合规**：单组单标签时不展示标签条；多标签超出视口时，以 MRU 顺序收纳至“更多 N”下拉菜单并准确显示运行中状态；达到 24 个视图上限时友好拦截并弹出视图管理器。
- [ ] **右栏全宽正名落地**：右栏全宽明确为“右工具区临时展开”，与“移至主工作区”文案清晰区分，不篡改布局拓扑，不写入持久化配置。
- [ ] **外部拖入防误劫持**：外部物理文件拖入、操作系统标题栏拖拽原生窗口、编辑器正文选中文本、终端内文本拖拽，均不被工作台内部拖放系统错误拦截。
- [ ] **异常中断安全回退**：拖拽过程中按 `Esc`、操作系统失焦、所属项目切换、远程 Host 断网，拖拽事务无条件瞬时撤回，遮罩光标干净复原。
- [ ] **旧数据迁移兜底完备**：测试覆盖损坏 JSON、丢失会话元数据、旧版非常规比例拓扑；旧版 5～8 格降级为四宫格且后置会话作为标签保留，并弹出一次性通知，绝不静默清空用户工作区。
- [ ] **实时订阅预算受控**：工作台任意状态下，全量实时流订阅严格控制在 8 路以内，优先级算法按 §9.5 精准运作；预算外隐藏会话切回走标准 Resume 流程，后台任务不中断，消息不遗漏。
- [ ] **无障碍与键盘全功能**：所有拖拽操作均有对应的右键菜单和快捷键替代方案，DOM Tab 切换顺序与视觉呈现严格匹配，屏幕阅读器文本包含清晰的角色与所属会话说明。
- [ ] **跨平台实机门禁**：首发必须在 macOS Tauri 真实环境中通过全量门禁；若同批发布 Windows 版本，必须在 WebView2 实机下全量复测，坚决不用纯浏览器 Chromium 代理测试。

### 11.3 性能基准验收指标
在基准硬件设备上固定视口分辨率、固定消息推送流速及画布复杂度，执行以下严格验收：

1. **落点预览响应时延**：拖拽指针移动到边缘判定带，半透明预览遮罩渲染的 **p95 时延 ≤ 50ms**。
2. **事务提交主线程阻塞**：释放鼠标到最终完成 DOM 投影与焦点重置，**主线程长任务阻塞时间 < 100ms**。
3. **高频移动内存稳定性**：连续执行 20 次跨区拖拽移动并静置后，JS Heap 与 DOM 节点数必须回落至基准线，无事件监听器泄露，无孤立的 Detached DOM。
4. **并发流式输入无劣化**：主舞台同时激活 4 个高速打字流式会话时，用户在当前聚焦会话的键盘输入响应与单窗基线对比无肉眼可见劣化。

### 11.4 内测指标与后续批次决策体系

> [!NOTE]
> **本地匿名数据度量**  
> v1 阶段先在 Feature Flag 下启动小范围内测。鉴于 Desktop 客户端尚未建立完善的用户端遥测链路，首批指标**全部在本地匿名累计计数**，内测用户可在设置中手动导出诊断包；指标纯粹用于支撑第二批与第三批的功能排期决策，不作为发版阻断门禁。

| 本地埋点指标项 | 数据洞察目的与决策指导意义 |
| :--- | :--- |
| **多窗分屏（≥2 组）使用率与停留时长** | 评估分屏是否真正成为高频刚需；若单窗占比 > 90%，需审视分屏入口与可用性 |
| **分屏后短时间内（< 30s）退回单窗比例** | 灵敏捕捉分屏体验负反馈（如尺寸狭窄、焦点错乱、主线程卡顿） |
| **拖拽操作与快捷键/菜单操作比例** | 评估视觉把手的直观度与可发现性，决定是否需要强化操作引导 |
| **单组用户误入标签条的次数** | 确认侧栏点击不再堆标签；若仍出现，检查持久化收拢与分屏拖入路径 |
| **首批三类工具移入主舞台的频次与时长** | 量化评估工具跨区的真实生产力价值，避免伪需求 |
| **未开放工具被拖拽尝试的次数（按工具分别统计）** | **直接决定第三批工具开放的排期优先级**（高频受挫的工具优先开放） |
| **跨项目拖拽被拒后点击“切换项目”的转化率** | 论证未来是否有必要投入资源研发“单工作台混排多项目”能力 |
| **预算外隐藏会话切回时的加载耗时分布** | 论证未来是否有必要立项研发复杂的“Host 增量暂停/补齐协议” |
| **右栏“临时展开”与“移至主工作区”使用比例** | 评估用户更偏爱哪种放大审查模式，作为后续交互简化的依据 |

## 12. 验收闭环与关联文档

### 12.1 关联文档同步要求
首批功能正式上线前，必须同步更新以下工程文档：
- **ADR 0063**：详细沉淀主舞台最多四格、单组折叠呈现、无损降级迁移及最近关闭栈的设计决策。
- **ADR 0020 & ADR 0057**：同步更新浏览器镜像租约与画布视图在跨区移动中的保活生命周期。
- **产品文档**：全面修订原有关于“右栏全宽”的描述，更新为“右工具区临时展开”，消除歧义。
- **注**：关于终端 PTY 独立生命周期的 ADR 0013，待第二批切片 F 正式实施时再行更新，严禁提前写成已上线。

### 12.2 工程质量守则
1. **边界纪律**：严禁在 `apps/desktop` 壳层引入 `@earendil-works/pi-*` 依赖；所有跨层调用必须经由 `@piwin/contracts` 与 `@piwin/host-client`。
2. **代码规模控制**：严格遵守单个源码文件不超过 `1000 行` 的硬性约束；当文件逼近 `400 行` 时主动按职责（策略、状态、视图、宿主）进行物理拆分。
3. **提交原子性**：纯代码架构重构（Refactoring）与具体用户行为变更（Behavior Changes）必须拆分为不同的独立 Commit 提交，严禁混杂。

### 12.3 最终完成定义 (Definition of Done)
> **v1 最终达标标准**：  
> 用户能够在最多四格的主舞台内，行云流水地拖动排列会话以及浏览器、变更/Diff、文档/画布；可随时通过快捷键找回关闭的视图；移动、分屏、成组全程**不丢失草稿输入、不串投交互会话、不中断底层执行进程、不丢失页面状态**；在极端小窗或临时全宽展开后，能平滑无损地还原用户精心调整的工作台布局。
