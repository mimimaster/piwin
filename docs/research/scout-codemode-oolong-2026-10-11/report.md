# Scout 之外，Codemode 在 OOLONG 长任务中是否有收益？

**本批没有验证“更省 Token、更快且不降低正确率”。** 新闻题 B 未调用 Codemode；长问答题 B 的累计 Token 较低，精确正确率也较低；否定句计数题有效样本和用量不足。不能把脚本测试通过或上下文压缩当作性能优势。

选择 [OOLONG 官方项目](https://github.com/abertsch72/oolong)的[公开 OOLONG-synth 无标签数据](https://huggingface.co/datasets/oolongbench/oolong-synth)，固定 32K/64K/128K 标称长度的三题，完整原文通过只读文件访问。这是工具版改编，未运行整套官方评测；标称长度不是 Grok 实测 Token。新闻题只需筛选特定用户的六条新闻，因此输入长并不代表每次都需处理全文件。问答题则需对 1676 条记录做语义分类和聚合，不能直接读现成标签。

test-host 原生 xAI OAuth；主模型 Grok 4.5/high，全部 Scout Grok 4.5/low；Host SDK + Scout RPC，UltraCode readonly。每次新 Host/会话，A/B 交替，真实模型自主选择工具，A 保留 Scout/read/grep/bash，B 不强制 Codemode。固定源码、提示和模型配置；最终统一隔离阶段的十二次配置除 enabled 外 hash 相同。

18 个槽位全部占用，**4 个隔离相关中断、14 个有效协议观察**，没有补跑。四个中断不是模型答错，排除有效均值；新闻/问答仍各有 A/B 三次，首题只剩每组一次。源快照全部未变，未修改产品功能、主工作区或真实配置。隔离缺陷、阶段差异和凭据文件整体 hash 变化都在 [protocol.md](./protocol.md) 中披露；xAI 凭据对象未变，不能声称整个 auth.json 自始至终未变。

问答题 B 平均 Token 少 **19.5%**，其中未缓存输入均值 A 165,881 / B 167,439，缓存读取 A 543,445 / B 402,987，输出 A 49,609 / B 40,665。Token 减少主要来自缓存读取累计量减少，不等于已验证的金额节省。两组各一次 15 分钟截止超时，取消/清理的完整耗时未测，完整平均速度未知；不删除超时后包装成“更快”。

- 第二对：A 908,572 Token、623.18 秒、答对；B 746,908 Token、723.02 秒、答错为 Science & Mathematics。B 少 17.8% Token，却慢 16.0%。只看 B 主模型 118,844 Token 会漏掉 Scout 的 628,064 Token。
- 第三对：两组均答对，B 687,400 对 A 1,185,380 Token，少 42.0%；680.37 对 703.71 秒，快 3.3%。这是一个正向观察，不能抵消本题整体正确率从 2/3 到 1/3。
- 第一对：两组都超时；B 398,963 对 A 182,856 Token，更多。三次失败都纳入验收，不将超时或错误答案视作节省成本的成功。

否定句题 A 给出 264，gold 261，精确错误，数值部分得分 0.421875；B 超时没有答案。两次都有未完成 Scout，完整任务 Token 未知。四个中断占掉余下名额，不能据此比较首题性能。

## 三个问题的结论

1. **代码探索：未证实 Scout 之外的额外收益。** 本批只补测长数据任务，没有重新测代码探索；[前一批原生 OAuth 报告](../scout-codemode-oauth-2026-10-11/report.md)的代码题触发不足且部分用量缺失，仍不足以归因。
2. **结构化数据：收益依赖任务。** 前一批字段已确定的 4096 行 JSON 聚合，B 三次均实际使用 Codemode，累计 Token 少 63.9%、耗时少 43.1%、两组均 3/3 正确。本批无标签语义分类再聚合没有复制三项同时改善；不能将简单字段聚合的收益外推到所有长任务。
3. **错误率：不能宣称不下降。** 本批问答题 B 精确通过率较低；全部有效观察 A 5/7、B 4/7。这是启用策略的小样本结果，不能证明一般错误率、也不能将每个错误因果归于 Codemode。但已有反例足以拒绝本批“同时更省、更快且不降正确率”的结论。
