# Scout 之外，Codemode 是否有收益？原生 OAuth 实验

本批显示：**结构化数据题有明显收益；代码探索未证实额外收益；不能宣称整体正确率不下降。** 这是单机三次重复的描述性结果，不是泛化结论。

使用 test-host 的原生 xAI OAuth，隔离 Host SDK + Scout RPC，Grok 4.5 主模型 high / Scout low，UltraCode readonly。A/B 每次新会话，串行交替，除 `codemode.enabled` 外配置一致。固定代码快照和同一 4096 行 JSON。18 次真实自主工具任务全部执行，无补跑、无模型响应 mock；每次至少一个 Scout。源码、产品行为和真实配置未修改，源 OAuth 文件前后 SHA256 一致。

## 三个问题的答案

1. **代码探索有没有收益？没有得到可靠证据。** 调用链题 B 平均耗时反而多 20.7%，准确率从 3/3 到 2/3；完整 Token 缺失，不能比较。跨文件题 B 平均 Token 少 12.0%、耗时少 2.6%，但只有一次 Scout 尝试 Codemode且失败，随后使用普通工具完成。A 第二次自主启动三个 Scout，其他跨文件运行各一个，贡献了较大波动。不能把这组均值差异归因于 Codemode。
2. **结构化数据有没有收益？本题有。** B 三次均由 Scout 自主使用 Codemode；主模型 + 全部 Scout 平均 Token 从 272,356 到 98,203，少 **63.9%**，耗时从 62.93 秒到 35.84 秒，少 **43.1%**。三对分别节省 Token 66.7%/64.0%/60.5%，均更快。A 主模型正常使用只读 bash 等命令，能力没有人为禁用；A Scout 的普通 read/read_file 返回较大数据，B Scout 在 Codemode 内读取并聚合后返回短结果。解释与工具证据一致，但 n=3 仍不足以证明一般场景都会受益。
3. **是否伴随错误率上升？数据题未观察到答案错误增加，两组均 3/3；整体 B 有一次调用链错误，A 9/9、B 8/9。** 不能宣称“不降低正确率”。该错误是 prepareResolvedPath 引用第 417 行空白，函数范围是 396–416；这次没有实际调用 Codemode，不能归因于 Codemode。数据题 B 的 10 次 Codemode 调用有 2 次工具失败，模型纠正后最终全部答对；这些失败的 Token 和耗时已计入。

## 可信边界与交付

- **测量缺陷**：运行中的回调漏记子事件，且 RPC worker 过滤环境变量，前五次 Scout 的原生记录在发现问题前已清理。第六次起只读补采，13 次完整 Token 对账成功，不补跑。编号原始 JSON 的 `scoutCount=0` 和 `observedUsage` 是有缺陷的原始采集，后者只含主模型；以带来源的 [metrics.json](./metrics.json) 和 [runs.csv](./runs.csv) 为准，不把漏记当成零用量。
- 主模型全部真实 HTTP 200，SSE 总 Token 与 Host ledger 一致；第 6–18 次主模型再与原生 Pi usage 一致，全部 Scout 原生末次 stop 完整。缓存读取、未缓存输入、输出、reasoning 的逐运行分项都保留。cacheWrite、全部 Scout 模型重试、供应商内部重试和工具重试次数未知；主模型可观察模型重试为 0。工具失败次数不等于重试次数。
- 数据 B1 记录 4 次内嵌调用；B2/B3 的部分失败结果没有内嵌明细，总内嵌次数未知，已观察的下限分别 3/2。未知不影响生成用量和端到端耗时。所有已确认的 Codemode 调用来自 Scout；主模型直接 Codemode 调用为 0。
- 每次固定提示 hash、去掉 enabled 后配置 hash、代码/夹具 fingerprint 均一致；每次源码内容保持不变。顺序固定从 A 开始、供应商缓存/负载及自主 Scout 数仍是小样本局限。不做显著性或正确率非劣效声明，不报金额。
- [protocol.md](./protocol.md) 提供可复现命令、环境与固定验收；[manifest.json](./manifest.json) 保存完整任务与 oracle。编号 JSON 保留原始主事件/SSE/ledger/答案；[native-recovery](./native-recovery/) 保留逐请求 Scout usage、工具及会话归属证据；[source-auth-integrity.json](./source-auth-integrity.json) 记录源凭据哈希一致。均不含密钥。
- 原非 OAuth 批次的 18 次 HTTP 426 阻塞报告单独保留在 `../scout-codemode-2026-10-11/`。用户要求切换 OAuth 后，本批重新编号、18 次封顶，两批不混合计算。

实验脚本 7 项检查通过，仓库 `pnpm typecheck` 和包边界检查通过；这只验证采集/验收脚本与工程约束，不能当作性能更优的证据。
