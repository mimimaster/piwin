Workspace 写锁改动报告

修的是 Host 写盘锁，不是进程分工。Worker 仍然只读；写文件、bash、Git、合入还是 Host 执行。

1. 改了什么现象

之前

一轮里并行写 3 个不同文件，后两个立刻失败：workspace-busy。长 bash、Git、合入也会把别的写打掉。

现在

不同文件可以一起写。同一文件排队。bash / Git / 合入会等，不再对模型报 busy。只有撤销撞锁才立刻 busy。

2. 现在每类操作怎么锁

操作锁撞车时
write_file / delete_file 工作区共享 + 该文件独占 等待。不同文件并行
bash / run_bash 整仓独占 等待
Git 写、子代理合入父仓 整仓独占 等待（合入仍先走自己的仓库队列）
undo / redo 整仓独占 立刻 workspace-busy，不排队
读文件、列目录、Git 查询 不加锁 —

3. 顺手补上的洞

  • 父子项目根互斥：/repo 和 /repo/packages/foo 不能同时独占。
  • 新文件走目录软链接（real/new.ts 和 alias/new.ts）锁同一把。
  • undo 真正接到这把锁上；以前类型里有、实现没取锁。
  • 等待可取消（Run 的 AbortSignal）。Git 命令这条 IPC 仍不能从客户端取消。

4. 动了哪些代码

位置做什么
packages/git path-policy 公开文件身份：resolveFileLockKey
workspace-write-gate.ts fail-fast 整仓锁 → 公平 FIFO + 共享/独占
文件系统工具 / bash 写删走文件锁；bash 走整仓独占
Git 命令、integrate、undo 按上表接线
ADR 0069、ADR 0030 记下决策；合入改为等待而不是立刻失败
