# 关于 Piwin · 诞生的故事与初心

> 一个日常重度写代码的个人开发者，为自己打磨的随身编程搭档。  
> 不玩虚头巴脑的宏大概念，只求用着顺手、配置省心、省钱靠谱。

---

## 1. 为什么做这个工具？

在过去的一年多里，市面上涌现了无数优秀的 AI 编程工具与尝试。作为一个工程重度开发者，我自费体验了几乎所有主流产品：Cursor、Devin、Windsurf、Claude Code、Codex、Kiro、Qoder、Grok Code 等等。

但在长期实际开发中，我经常遇到几个让人抓狂的痛点：

- **配置繁琐折腾**：想换个模型或者接个官方订阅，经常要找中转反代、写一大串环境变量、或者在几个客户端之间反复切换；
- **上下文污染太狠**：对话稍微一长，读取的文件一多，主模型的上下文窗口迅速被塞满，代码越写越容易胡说八道；
- **官方订阅用不痛快**：明明手里握着 Kimi Code、Claude、Codex 等官方套餐，却找不到一个能够一键授权、舒心调度的主界面；
- **看图 Token 烧得肉疼**：写前端或者看报错截图，动辄把几兆的高清图丢给昂贵的深度推理模型，不知不觉账单飞涨。

与其在各个商业产品间反复受气，不如做一款**真正面向个人开发者、配置自由、用着省心顺手**的编程工作台。这就是 Piwin 的起源。

---

## 2. 一切为了日常开发的顺手与省心

我们在功能取舍上只关注一点：**它能不能让你在日常写代码时少费心、少花冤枉钱？**

| 痛点 | 我们的解法 | 实际收益 |
| :--- | :--- | :--- |
| **折腾模型配置** | 官方订阅一键 OAuth 授权，各类标准 API 填 Key 即用 | 不用自建中转反代，两分钟连通开工 |
| **长上下文污染** | 引入 Code Search 机制，派出只读子代理摸排拓扑 | 主模型上下文永远干干净净，只看结论 |
| **看截图浪费 Token** | 视觉委托机制，让免费的 Gemini Flash 或轻量模型先看图 | 毫秒级提取界面结构，省下一大笔 Token 账单 |
| **实时资料检索** | 内置 Tavily（每月免费 1000 次）、Brave 与 Devin Token | 查最新框架版本 API 和 Issue 不卡手 |
| **怕代码被改乱** | 子代理在独立的 Git Worktree 里写，人工审查后再合并 | 绝不污染当前工作区，不合心意随时丢弃 |

## 3. 为什么叫“吃百家饭”？

“吃百家饭”包含两层意思：

1. **设计上博采众长**：深度体验了各类优秀工具，把真正好用的交互（Devin 的代码检索与 Token、Codex 的 Ultra Code 侦察、Astra 的实时语音、Pi 的扩展机制）融汇到一个顺手的界面里；
2. **开发上千锤百炼**：项目在构建过程中充分借助了各家强模型的推理与自检，历经无数次重构与实战打磨。
