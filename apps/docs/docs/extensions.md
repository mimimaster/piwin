# Pi 扩展生态与热加载机制

**Piwin** 深入拥抱 **Pi 扩展生态**，原生支持把兼容的社区 Pi 插件和能力无缝接入到当前会话中。

本文档将详细介绍 Pi 扩展的安装、热加载机制、能力边界与最佳实践。

---

## 1. 核心特性：会话中热加载 (Hot Application)

传统开发工具在安装新插件后往往需要重启整个软件，导致正在进行的会话上下文丢失。

在 Piwin 中：
1. **无需中断工作**：当当前任务正在执行时安装新扩展，Piwin 会先优雅等待当前 Run 顺利结束；
2. **下一轮自动生效**：在下一轮对话开始时自动挂载并激活新拓展，完整的会话历史树与聊天记录被 100% 完整保留；
3. **扩展市场支持**：支持直接从市场搜索安装或通过 Git URL、本地路径快速加载。

---

## 2. 支持的能力范围与边界规范

| 扩展能力类别 | 支持状态 | 具体表现与说明 |
| :--- | :--- | :--- |
| **Agent 工具 (Tools)** | 完全支持 | 扩展提供的自定义工具直接注册进当前 Host 工具箱，智能体可自主调用。 |
| **事件 Hook (Event Hooks)** | 完全支持 | `session_before_compact`、消息拦截、状态监听等 Hook 完整生效。 |
| **Provider 自定义扩展** | 完全支持 | 支持接入第三方模型或服务的 Provider 扩展。 |
| **交互对话框 (Dialogs)** | 完全支持 | 基础的确认（Confirm）、选择（Select）、输入（Input）与通知（Notify）弹窗正常由桌面端原生渲染。 |
| **混合界面扩展** | 部分可用 | 若扩展主要提供 Agent 工具但附带少量终端界面代码，Piwin 会标记为“部分可用”：工具能力正常工作，终端 TUI 界面被安全忽略。 |
| **纯终端 TUI 扩展** | 不支持 | 仅修改 Pi 终端 TUI、终端主题、终端快捷键、字符编辑器的扩展无法在 Desktop 中启用。 |

::: warning 关于重载方法的注意
扩展代码中自带的 `ctx.reload()` 并不会直接硬重启当前 Desktop 运行时；在桌面端中，请在扩展管理卡片上点击 **「应用到当前 Agent」** 进行平滑热生效。
:::

## 3. 扩展安装方式

### 3.1 客户端图形界面安装
1. 在聊天面板或快捷命令中唤起扩展市场；
2. 搜索所需扩展并点击安装；
3. 系统自动下载并存放在用户目录 `~/.piwin/extensions/<name>/`。

### 3.2 智能体自动安装 (Tool 调用)
在对话中直接告诉智能体“帮我安装一下某个扩展”，智能体会调用 `extension_install` 工具完成拉取与激活。
